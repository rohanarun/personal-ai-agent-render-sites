Reliability dynamics

A retry is new load wearing an old request’s name.

When arrivals exceed service capacity, queue delay grows. Timeouts trigger retries, retries raise arrivals, and the feedback loop can collapse a healthy dependency. Backpressure turns infinite waiting into explicit admission, pacing, and recovery decisions.

Push the system past capacity. Then recover it.

The control loop

Admit. Pace. Recover.

Bound waiting

A queue limit converts invisible latency growth into an explicit rejection signal. The caller can degrade gracefully instead of waiting forever.

queue ≤ finite capacity

Decorrelate retries

Exponential backoff with jitter spreads retries across time. Without jitter, clients synchronize and strike the recovering dependency together.

delay = random(0, base · 2ᵃᵗᵗᵉᵐᵖᵗ)

Open the circuit

A circuit breaker stops calls after repeated failures, gives the dependency time to recover, then admits a small probe before closing.

closed → open → half-open

Tail latency

Average latency can remain calm while queued requests accumulate. Watch p95 because agent steps often wait for the slowest required tool.

Retry budgets

Retries should consume a bounded budget, not multiply indefinitely. A single request must never generate unlimited downstream work.

Graceful shedding

Drop low-priority or stale work early. Completing fewer useful requests beats timing out every request after expensive partial execution.
