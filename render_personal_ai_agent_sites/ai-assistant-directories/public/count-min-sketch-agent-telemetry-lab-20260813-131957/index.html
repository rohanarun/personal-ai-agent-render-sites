Streaming frequency estimation

Trade an exact map for a bounded overcount.

An agent platform can track tool calls, cache keys, retrieval documents, or browser actions with memory that never grows with the number of unique events. Width controls collision error. Depth controls the probability that every row collides badly.

Why the minimum works

Every collision can only add.

Update

Hash each event into one counter in every row, then increment those counters. Standard updates touch every selected cell.

table[row][h_row(event)] += 1

Estimate

The true count contributes to every selected cell. Collisions add nonnegative noise, so the minimum selected counter is the least contaminated estimate.

estimate(x) = min_row table[row][h_row(x)]

Bound

With width proportional to 1 / epsilon and depth proportional to ln(1 / delta), the overcount is at most epsilon times the stream mass with probability at least 1 - delta.

width = ceil(e / epsilon), depth = ceil(ln(1 / delta))

Heavy hitters

Large events stand above collision noise and can be ranked without keeping a counter for every unique key.

Conservative updates

Increment only cells currently equal to the row minimum. This reduces avoidable overestimation while preserving one-sided estimates.

Mergeable summaries

Sketches with identical dimensions and hashes can be added cell by cell, making distributed telemetry aggregation straightforward.
