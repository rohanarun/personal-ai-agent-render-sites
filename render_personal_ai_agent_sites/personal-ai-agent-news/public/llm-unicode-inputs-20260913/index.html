What changed?
NFC composes canonically equivalent text where possible; NFD decomposes it. NFKC and NFKD additionally apply compatibility mappings. Try fullwidth letters with NFC and then NFKC: the compatibility form removes the width distinction.
Unicode warns against blindly applying compatibility forms: distinctions they remove can matter. Normalization is not a general text-cleaning rule, case folding, translation, or a defense against all look-alike characters.
For an LLM experiment, record the exact preprocessing used. This display counts code points and UTF-8 bytes, not visible characters or model tokens. It does not predict token savings, cache hits or model behavior. Test those separately with the actual pipeline.
Implementation and source
The browser's String.normalize performs normalization; TextEncoder supplies UTF-8 bytes. The input stays in this page, with no persistence or model request. The displayed result depends on the browser's Unicode implementation.
