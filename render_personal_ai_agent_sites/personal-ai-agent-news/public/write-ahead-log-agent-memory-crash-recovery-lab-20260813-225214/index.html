Durable AI-agent memory

Log the change before touching the page.

Write-ahead logging makes an agent-memory update durable before its data page is flushed, so a crash leaves a replayable history instead of an unexplained gap.

Durability begins with ordering.

The core promise is simple: the log record reaches stable storage before the corresponding data page can claim the update exists.

Append

Assign an ordered log sequence number.

Each memory mutation records enough information to repeat the change and receives a monotonic position in the log.

Flush

Make commit depend on stable WAL.

The transaction acknowledges only after its required log records are durable, while data pages may lag behind.

Replay

Redo committed updates after restart.

Recovery starts from a checkpoint and reapplies durable records whose pages had not yet reached storage.
