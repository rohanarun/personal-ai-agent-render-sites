Make proof expire honestly

A checkpoint should carry the assumptions that make it useful and the invalidation signals that make it safe.

Trust stable proof

Reuse a recent checkpoint when the environment is stable and the consequence of a stale assumption is bounded.

Refresh volatile state

Recheck the world when time or volatility could have changed the fact that the checkpoint depended on.

Invalidate before harm

Drop proof that is too old for a high-consequence action, even if it once passed every check.

This simulation is a teaching model, not a production checkpoint policy. It demonstrates a contract-first pattern: bind proof to assumptions, age, volatility, and consequence.
