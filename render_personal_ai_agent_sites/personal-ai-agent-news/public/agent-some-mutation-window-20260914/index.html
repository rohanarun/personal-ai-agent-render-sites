The scan starts with inspect, plan and report. At its first callback, the selected mutation runs. Appending urgent creates index 3 beyond the original length, so that entry is not tested in this invocation. Replacing index 1 changes the value observed when the callback reaches it.
Deleting index 1 leaves a hole rather than shifting the array. The callback skips that absent index in this plain-array fixture. The final slots explicitly distinguish absent properties from present strings; they are not serialized as an ambiguous null-filled array.
A match ends the search
The callback asks whether its value equals urgent. Replacement therefore returns true at index 1 and skips index 2 because the search has already succeeded. Appending returns false despite urgent being present afterward. The boolean describes the scan that ran, not an immutable statement about the final queue.
MDN's Array.some reference documents early termination, captured length and mutation behavior. This lab uses the native method. Its export records actual visits, the returned boolean and the final own-property slots.
Do not turn a predicate into a dispatcher
The work labels are illustrative. No agent task or external action runs. In a real queue, changing membership while validating it can make the evidence hard to interpret. Separate admission from scanning, or deliberately define how the consumer handles changes. A different iterator can follow different rules; the linked live-queue lesson explores that distinction.
This fixture uses a synchronous callback, ordinary strings and a plain array with no inherited numeric properties. It does not demonstrate asynchronous predicates, proxies, concurrent workers or arbitrary sparse-array inheritance. Avoid assuming the observed hole behavior covers all objects with array-like keys.
Each scan creates a new queue. Changing the case or resetting clears the previous evidence; it does not modify a production queue. No model or network API is called. Published September 14, 2026 by Super Powers AI.
