Agent Log Pattern Lab

One flag changes line boundaries. Another lets a dot cross them. The difference can turn a single log entry into a match spanning several events.

Global matching (g) is always enabled.

Anchors are not dots
Multiline mode changes the positions where ^ and $ can match: a line's boundaries can qualify, not just the input boundaries. It does not make . consume the newline. In the ERROR pattern, turning on m alone finds the two separate error lines.
Dot-all mode lets . match line terminators. With both m and s enabled, the greedy .* in the ERROR pattern can continue through later lines to the end of this input. The match then includes an INFO line and the final END marker. Finding more text is not necessarily extracting better evidence.
Greedy versus lazy
The BEGIN patterns have no anchors, so toggling m does not change their results. Without s, neither crosses the line breaks. With s, BEGIN.*END reaches the last END, while BEGIN.*?END stops at the first available END for each match. The lazy version finds two blocks in this fixture.
That does not make lazy matching a general parser. An END inside quoted content, nested blocks or a partial streamed record could still break the assumed structure. For agent tools, prefer structured records with explicit fields when the source provides them; treat regex output as a candidate extraction, not authenticated proof of a successful action.
What this run proves
This page calls the browser's native RegExp and matchAll on a fixed illustrative log. Highlighted regions are exact matched substrings; offsets are zero-based UTF-16 code units, with the end excluded. Newline characters remain in the exported strings even when the highlight between lines is visually subtle.
The input is deliberately bounded and the three patterns are fixed. This is not an arbitrary-regex executor, performance benchmark, production-log validator or model evaluation. Export contains the input, pattern, flags and actual matches. Nothing is uploaded or executed by an agent.
