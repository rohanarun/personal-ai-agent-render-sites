Safe and exact are different questions
9007199254740992 is representable, but it is outside JavaScript's safe-integer range. Its adjacent integer 9007199254740993 rounds when parsed as a Number. A particular exact value outside the safe range does not make neighboring values reliable.
Preserve identifiers as identifiers
Illustrative agent handoff: a service supplies a long record ID and a later tool must address that exact record. When the API contract allows a string, preserving the original digits avoids this numeric conversion. Do not change a real API's schema without checking its contract.
Different JSON implementations can have different numeric limits. This page demonstrates this browser's JSON.parse and Number behavior, not every language or provider. BigInt is used only for the exact comparison; report fields are strings because JSON does not directly encode BigInt values.
What this does not validate
A preserved ID can still refer to the wrong record or lack authorization. This experiment does not validate schemas, permissions, existence or model output quality. It also excludes fractional numbers and exponent notation to keep the integer comparison explicit.
