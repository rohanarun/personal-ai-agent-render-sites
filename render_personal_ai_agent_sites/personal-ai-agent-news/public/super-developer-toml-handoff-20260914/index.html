Structure survives; syntax does not

TOML supports tables, dotted keys, arrays and several scalar types. Comments and the original formatting are not part of the JSON result. This tool targets TOML 1.0, not the newer 1.1 language additions.

The bundled smol-toml 1.3.1 parser performs parsing. This is not a complete conformance certificate: the parser documents Unicode and date-validation limitations. Pasted text also cannot establish the original file's UTF-8 validity.

Deliberate conversion boundaries

This reviewer rejects all parsed date/time values rather than silently turning them into JSON strings. It also rejects non-finite numbers, unsafe integers and negative zero. Those are export restrictions, not claims that the input is invalid TOML.

Other decimal values may still round in JavaScript. Integer-versus-float spelling is not preserved. Keep the original file for exact numeric or textual fidelity; this is not a lossless migration tool. Empty TOML produces an empty object.

The input limit is 100,000 characters and the parsed structure is limited to 50 nesting levels. Parser failures and unsupported values block the entire export. Editing the sample invalidates the old result. The example is illustrative, not a configuration for Super or any deployment platform.

Review before replacing a configuration

Compare expected keys, types and nesting with the consuming application's schema. A valid document does not prove that a field is recognized or that a service can start. This page does not load environment variables, resolve includes, deploy changes, or contact an agent.

Use non-sensitive samples. Parsing happens in this page with the bundled library; no input is sent to a model. The first-party demonstration below loads remote media separately. The downloaded JSON contains your parsed values and must be reviewed before sharing.
