Compose before cancellation
AbortSignal.any creates a signal that aborts when an input does. Compose first, then abort B. The combined reason becomes B's reason; A remains active. Aborting A later does not replace the combined reason.
Compose after cancellation
Start fresh, abort B, then A, and compose with A listed first. Both are already aborted, so the first already-aborted input in iterable order supplies the reason: A. This differs from constructing the combined signal before the same sequence of aborts.
The experiment uses two real AbortControllers with distinct string reasons. Composition happens once per fixture. New controllers discard the trace and create new source objects; they do not restore a canceled signal. The state panel inspects the native signals after each action.
Reason is not the whole history
A single combined reason cannot serve as a full causal audit of all cancellation requests. Preserve source observations separately if your agent needs that history. Composition is not a command to cancel the remaining sources, and it does not roll back completed work.
This page has no running job, timeout or external request. It demonstrates signal composition, not proof that an agent, remote tool or sibling task stopped. A consumer must actually cooperate with its signal. The JSON trace exports source states and actions, not live controllers.
