Async Predicate Trap

An agent's validation gate is only as sound as the value it actually tests. A Promise object is not a completed check.

    Why the gate opens too early
    Array.every tests the truthiness of each callback return. An async callback returns a Promise, which is truthy even when it will fulfill with false. The mistaken path therefore returns true immediately. Awaiting that final boolean does not repair it.
    In this experiment, three fictional checks settle after timer delays. The faulty path starts them all; the awaited path starts one at a time and stops on false. With evidence rejected, the last check is never started in the awaited path. The trace records real browser execution, not a simulated schedule. Timer durations are illustrative minimum delays, not latency benchmarks.
    A useful boundary for agent systems
    Do not dispatch an action merely because asynchronous validation was requested. Wait for its result and handle errors separately. This lab uses only fulfilled booleans: real checks may reject, need deadlines, or require cancellation. It does not implement an authorization system, perform network checks or call a model.
    Parallel validation is another policy: await all results, then test the resulting booleans. That starts every check and does not offer this loop's early-stop behavior. Choose deliberately when checks have costs or side effects.
