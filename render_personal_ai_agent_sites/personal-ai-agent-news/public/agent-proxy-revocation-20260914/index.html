Two paths to one counter
The fixture creates an ordinary object with a nested {count: 0} object, then wraps the outer object using Proxy.revocable with an empty handler. Retaining the nested reference performs a real proxy.nested read before revocation.
Revocation disables subsequent operations such as property reads through that proxy; those reads throw TypeError. It does not transform the separate nested object into a proxy. An earlier retained reference still points to that ordinary object and can change its count.
Run the boundary experiment
First retain the reference, revoke, read through the proxy, then increment the retained count. The wrapper read fails while the count changes. Start a new fixture and revoke before retaining: there is no captured reference in this run, and the increment remains unavailable.
The state panel reads the original target held by the lab so the effect is visible. A revoked proxy remains revoked; the new-fixture command constructs different objects rather than undoing revocation. Repeating revoke is harmless. The trace exports ordinary observations, not live references.
Agent integration consequence
A plugin API that exposes nested mutable objects needs an explicit reference policy. Revoking an outer wrapper alone is not transitive access revocation. Depending on the architecture, return copied data or separately controlled operations instead of handing out unrestricted mutable references.
This is a local language-semantics experiment, not a sandbox, access-control implementation, network cancellation test or proof that an agent has stopped. Already completed effects are not rolled back. No model, provider or external action runs here.
