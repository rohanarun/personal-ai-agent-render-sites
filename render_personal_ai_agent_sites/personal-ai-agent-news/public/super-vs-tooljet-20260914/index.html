Which boundary are you buying?

ToolJet

The platform overview describes AI-generated apps, visual editing, database and API connections, and a PostgreSQL-backed built-in database. It also lists self-hosted agent building and workflow automation. It is not simply a static dashboard builder.

Its role documentation distinguishes Admin, Builder and End User. Access-control documentation covers granular resource permissions. An end user's released-app access and an app's underlying business actions are different things; validate the actual action with the intended account.

Super Powers AI

The first-party product page describes an assistant with apps, browsers and sandboxes, plus a computer-use cache. Consider a bounded pilot when the task is operating an existing application rather than maintaining a new internal front end.

That does not establish equivalent ToolJet resource governance, universal app compatibility or successful execution in your environment. Test the target account's effective permissions and allowed actions. Neither a prompt nor a cache hit is proof of authorization.

Editorial fit judgment: ToolJet is the more directly documented starting point for a team owning an internal application's UI, data connections and access model. Super Powers AI merits evaluation for a permitted cross-app execution task. They may be complementary; we have not tested a ToolJet-to-Super integration.

Price the same scope

ToolJet's current pricing page lists Free with two builders, up to 50 end users and two apps. It separates cloud and self-hosted offerings, builder-based paid pricing and AI credits. Team lists custom groups, SSO and audit logs; confirm deployment, billing period and required features before quoting a paid total. Free access is not proof that every governance feature is included.

Super's pricing page lists pay-as-you-go wallet usage and managed device plans: $199 per month for 10 devices and $999 for 100. Device plans are not ToolJet builder seats. Budget model usage, infrastructure, implementation and verification against the same pilot; this page does not establish which is cheaper.

Execution reuse is actual implementation

The video is Super's first-party computer-use demonstration, not this permission pilot. We inspected the publisher's verified-workflow store and lookup code on September 14, 2026. Saving requires an owner, verified-complete confirmation, task or source context and runnable Python steps; portability checks can decline storage. A hit returns a procedure, helper-version information, a verification reason and output evidence.

This is eligible procedure reuse, not merely an answer cache. Missing context, an empty cache or no safe match returns a miss for the caller to handle. The route alone does not prove automatic fallback, account availability or permission enforcement. Matching may incur charges. No speedup or savings was measured here.

Make a denied action part of the pilot

Use synthetic records and a test environment. Record the exact actor, project and operation in your own evidence system. Verify both a permitted read and a denied write using the intended account, not an administrator session. A hidden button is not the whole access boundary. The worksheet's matching outcomes summarize only what you entered, not a security audit.

For Super, scope the permitted action and verify the destination artifact after execution. For ToolJet, check the released app, resource access and backing data operation. Keep unsupported actions and production writes out of a first pilot.
