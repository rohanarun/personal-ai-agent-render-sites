One value is one record

JSON Lines places a valid JSON value on each line. A record can be an object, array, string, number, boolean or null. A blank line is not a record. A final line terminator is accepted; an extra empty line is reported. Windows CRLF line endings are accepted here.

The JSON Lines specification describes UTF-8 encoding and excludes a byte-order mark. This desk accepts pasted text, so it cannot certify the original file's byte encoding. It rejects a leading Unicode BOM and treats embedded escaped newlines as part of a value, not a record boundary.

Errors stop the export

Validation reports original line numbers and value types. Any invalid record blocks the entire export; nothing is silently skipped. A successful export wraps the parsed values in one JSON array. It is not another JSON Lines file. Editing the sample invalidates the previous result.

This bounded reviewer accepts up to 100,000 characters and 500 records. It uses native JSON.parse: duplicate object keys keep their last value, numeric spelling is lost, and decimal values can round. Non-finite results, unsafe integers and negative zero are rejected to reduce obvious conversion surprises. Exact decimal preservation is not guaranteed. Do not use it for lossless archival, financial values or untrusted bulk ingestion.
