Object URL Lifetime Lab

A temporary artifact URL is a reference, not the artifact itself. Revoke it, then test the remaining access paths.

Remove the reference
URL.revokeObjectURL() releases an object URL created for a Blob. Create one, fetch it successfully, revoke it, and attempt a new fetch. That final request should fail because the URL mapping is gone.
Now read the original Blob directly. Blob.text() still returns its text because this page retains that object. The earlier successful read also remains in the trace. Revoking a URL is not erasing all copies of its contents.
Artifact lifecycle is not access control
For an agent-generated download or preview, keep the URL alive for the consumer's required lifetime, then release it when it is no longer needed. Releasing a reference does not prove immediate memory reclamation. Nor does it undo a download, revoke another copy or invalidate a remote service's stored file.
This fixture performs operations sequentially. It does not claim what happens to every in-flight fetch or already-loaded media element if revocation races with loading. A new request after revocation is the boundary being tested. Browser error wording can differ; the trace preserves the actual error name and message.
A local handle is not a share link
The generated blob URL belongs to this browser environment. It is not a public hosting URL for another device. Exported evidence records the operations and returned text, not a durable hosted artifact. The two bars show this page's retained Blob and URL-reference state, not a memory measurement.
Input is copied into a new Blob when Create is pressed; it is then locked until Reset. Reset releases the old URL, drops this page's Blob reference and clears the trace. It does not erase prior exported files. No model, remote upload or arbitrary URL fetch occurs; Fetch URL targets only the URL created by this fixture.
