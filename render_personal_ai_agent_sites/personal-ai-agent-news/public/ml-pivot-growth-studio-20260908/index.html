Row swaps protect the division

At each elimination stage, partial pivoting selects the largest absolute entry in the remaining pivot column. A permutation records the row swaps. The library returns unit lower triangular L and upper triangular U, satisfying P A = L U up to floating-point error.

Tiny example: A = [[epsilon, 1], [1, 1]]

Without a row swap, the first multiplier is 1/epsilon and the final pivot is 1 - 1/epsilon. With partial pivoting the multiplier becomes epsilon and the final pivot becomes 1 - epsilon. A tiny leading entry is not a reason to divide by it.

A family that grows anyway

The controlled matrix has diagonal entries one, entries -a below the diagonal, zeros above it, and a final column of ones. In its original row order, for 0 <= a <= 1, the implementation keeps the current row on a pivot tie. The last U column is 1, (1+a), (1+a)2, and so on. At a = 1 its largest entry is 2n-1.

Rotating the input rows changes tie order, so the factors and growth can change even though the linear system is only reordered. Pivot ties are not unique. Reset restores the original row order.

U-growth here means max(abs(U)) / max(abs(A)). The classical growth factor also includes intermediate elimination entries; those are not measured here. They coincide for the unrotated controlled family. Large growth is a stability warning, not a measured solution error or a condition number. Residual is ||PA - LU||F / ||A||F; multipliers exclude the diagonal of L. All arithmetic uses JavaScript double precision and ml-matrix LU.
