Probabilistic distinct counting

Duplicates vanish. Rare patterns remain.

A long run of zero bits is unlikely. HyperLogLog divides hashed events among registers, remembers the longest run observed in each, then combines those independent clues with a corrected harmonic mean.

Watch unique keys lift the register skyline.

Each hash selects one register with its prefix. The remaining bits determine rank: one plus the number of leading zeros. Duplicates usually leave the skyline unchanged.

The estimator

One rare bit pattern becomes evidence.

Partition

Use the first p hash bits to select one of 2^p registers. More precision means more independent buckets and lower variance.

j = prefix_p(hash(x))

Observe rank

Count leading zeros in the remaining hash bits and retain only the maximum rank ever seen in that register.

M[j] = max(M[j], rho(hash(x)))

Combine

Apply a bias constant and harmonic mean. HLL++ adds sparse representation, improved bias correction, and better small-range behavior.

E = alpha_m m^2 / sum(2^-M[j])

Duplicate immunity

Repeating an existing key reproduces the same hash and cannot lower or repeatedly increment its register.

Distributed merge

Sketches with the same precision and hash function merge register by register using maximum, with no raw events exchanged.

Precision tradeoff

Expected relative error is about 1.04 divided by the square root of the register count, while memory grows linearly.
