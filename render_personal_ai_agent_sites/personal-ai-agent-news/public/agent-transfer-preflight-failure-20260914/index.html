Serialization comes before this transfer
The function case adds callback: () => {} to an otherwise plain payload. Functions are not structured-cloneable. The duplicate case lists the same buffer twice. Both throw DataCloneError before this buffer is detached. A new view can still read its original bytes.
The valid case returns a payload containing those bytes and detaches the original buffer. The source now reports zero byte length; constructing a new view on it throws TypeError. A detached buffer is not merely an ordinary empty buffer.
Each attempt uses the native structuredClone API with a new buffer containing [17, 34, 51, 68]. The diagram, result and export come from measured properties and caught exceptions, not a simulated transfer outcome. No worker, server or model is contacted by the experiment.
A failure is not a universal rollback
This result is deliberately narrow: one ordinary ArrayBuffer, plain data, and either a function or duplicate transfer entry. Do not infer that every transferable resource or arbitrary getter has transactional rollback. Serialization may execute accessors, whose side effects are separate from buffer ownership.
For an agent handoff, keep executable callbacks outside the message data, avoid duplicate transfer entries, catch the exception, and inspect ownership before retrying. A successful local clone still does not prove a worker received, validated or completed a task. That needs its own acknowledgment and result evidence.
