Gradient clipping:
sphere or cube?

Limiting the whole vector preserves its direction. Limiting each coordinate can turn it.

Two different constraints
For a nonzero gradient vector g and positive threshold c, Euclidean norm clipping uses one shared multiplier. If the vector is too long, every component shrinks by the same factor. If it is already within the limit, nothing changes.
g_norm = g × min(1, c / ||g||₂)
For g=0, define the result as zero instead of dividing by zero. The output lies inside the sphere of radius c. This is the Euclidean projection onto that ball, and its direction matches the original nonzero gradient.
Coordinate clipping instead clamps each component separately:
g_value[i] = max(-c, min(c, g[i]))
Its output lies in a cube, not necessarily in the sphere. Different components can be scaled by different amounts, changing their ratios and therefore the direction. In three dimensions, the clipped vector can have Euclidean norm as large as sqrt(3)c. A component bound of one is not a whole-vector norm bound of one.
Try three revealing cases
  1. Unequal components. With g=(3,1,0.5) and c=1, the original norm is sqrt(10.25), about 3.2016. Norm clipping divides every component by that norm. Coordinate clipping gives (1,1,0.5), whose norm is 1.5. The rose arrow turns toward the less-dominant coordinates.
  2. Already small. With g=(0.2,0.1,0) and c=1, both transformations leave the vector unchanged. Clipping is a limit, not an instruction to stretch every small gradient to the threshold.
  3. Exactly zero. Both outputs are zero. No direction exists, so the angle display says undefined rather than reporting a meaningful zero-degree alignment. The arrows disappear because there is no nonzero vector to draw.
Why training code makes the distinction
Gradient norm clipping was studied as a way to address exploding gradients in recurrent networks by Pascanu, Mikolov and Bengio. The geometric comparison here illustrates the transformation; it does not train a recurrent model or reproduce their experiments.
PyTorch documents clip_grad_norm_ as computing a total norm over parameter gradients as if concatenated. For the Euclidean case, that means a shared scale across the chosen parameter set, not an independent limit for every tensor. Its clip_grad_value_ instead clamps gradient values within an interval. The choice of which parameters participate is part of the operation.
This page uses Three.js vector length and scalar clamping for the ideal mathematical operations. It is not executing PyTorch and does not reproduce implementation-specific numerical stabilizers. All inputs are finite and the threshold is positive.
A bounded gradient is not always a bounded optimizer step
For plain gradient descent with learning rate eta, the update is -eta times the clipped gradient. Norm clipping therefore bounds that update's norm by eta c. The arrows here show gradients, not the negative update direction, and no learning rate is applied.
Momentum, adaptive preconditioning and additional update terms change that simple relationship. Do not infer the norm of an Adam or momentum step from this picture alone. Clipping can also change the effective step size when the threshold activates; it does not repair an incorrect loss, bad data or non-finite arithmetic.
For a practical check, log the norm before clipping, the norm after clipping and the actual parameter update separately. Frequent clipping is information to investigate, not automatic proof of a healthy or unhealthy run. The right threshold depends on the training setup; this experiment makes no universal recommendation.
What to test
Test a zero vector, a vector below the limit, a vector exactly on the boundary and an unequal vector above it. Check the direction as well as the norm. A coordinate-clipped output may satisfy every component bound while violating the intended total-norm limit.
