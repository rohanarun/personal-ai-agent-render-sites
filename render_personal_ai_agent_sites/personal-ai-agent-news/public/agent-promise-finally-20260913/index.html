When Cleanup Replaces the Result

A settled task is not necessarily the result that reaches the end of its Promise chain.

Native JavaScript Promises, executed locally. No real task, cleanup operation, or model call occurs.

Run a chain to observe its outcome.

Finally is not a value mapper

original.finally(() => {
  return 'cleanup-value';
});

In this example, returning an ordinary value from finally does not replace the original fulfillment value or rejection reason. Returning a fulfilled Promise also preserves the original outcome after that Promise settles.

Throwing from finally or returning a rejected Promise instead makes the resulting chain reject with the cleanup failure. A fulfilled task can therefore become a rejected chain; an original task error can be superseded by a cleanup error.

Keep both pieces of evidence

An agent may finish its main operation and then fail to release a resource or write an audit record. Reporting only the last rejection loses the distinction between the work outcome and the cleanup outcome.

Record the original task result independently if your application needs to preserve it. Define how cleanup failures should be surfaced rather than silently swallowing them. The right recovery action depends on which operation failed and whether it had external effects.

The callback here has no parameters. It is not given the original value or reason. This lesson uses immediate settlement and does not measure network latency, cancellation, retries, or remote resource release.
