Input validation
A small systems simulator

A fast agent is still wrong when its input contract is vague.

Adjust how strict the input contract is and how messy the incoming request is. The lab shows why rejecting ambiguity early can be cheaper than repairing a whole downstream run.

Shape the contract

Strictness defines what the agent accepts. Ambiguity measures how much the request leaves unspecified.

Accept: the contract is strong enough for this request.

Read the boundary

Teal chips are requirements the contract covers. Coral chips are unresolved ambiguity that should be rejected or clarified.

Coverage = strictness - ambiguity.
