Intl.Collator compares strings using language-sensitive rules. German base sensitivity treats a and ä as equivalent for this comparison; Swedish treats them as different base letters. Switch the locale with the original pair and compare again.

Only the sign of a nonzero comparison result is meaningful, not its magnitude. The report records negative, zero or positive and includes resolved options from this browser. Locale data and runtime support matter; the requested locale is not silently presented as the resolved one.

A display tie does not merge records

This fixture places the two raw strings into a native Set as a second, independent check. It does not use collation to construct those keys. A zero comparison can coexist with two distinct keys. An agent deduplicating external records must use the source's identity contract, not infer identity from a display-order tie.

Try A versus a at base and variant sensitivity. Then try two identical strings. No trimming, case conversion or Unicode normalization is applied to input. Empty strings are allowed; two empty strings form one exact key. Whitespace remains part of each value.

Preserve the evidence

The JSON export keeps both original strings, their Unicode code-point sequences, the requested and resolved collation settings, the comparison sign, strict string equality and the distinct-key count. Code points are diagnostics, not glyph counts. A visible character can contain multiple code points.

This is a local browser experiment, not an identity-resolution model, a database collation test or an authorization policy. It makes no decision about two people, documents or accounts being the same entity. Use a human-readable comparison for presentation only where it fits your product; keep record identifiers governed by their actual contract.
