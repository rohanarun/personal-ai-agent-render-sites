The collision happened before SHA-256

Concatenating ["ab", "c"] and ["a", "bc"] produces "abc" in both cases. The digest receives identical bytes. Matching hashes here are not evidence that SHA-256 failed: the field boundaries were already lost.

A separator alone is not enough when it can appear inside fields. The delimiter example pairs ["a|b", "c"] with ["a", "b|c"]. Both join to "a|b|c". The JSON string-pair mode encodes the same two string fields with explicit structure and escaping, preserving their distinction.

Define identity before reuse

Illustrative agent scenario: a cache lookup depends on task text and context. Accidentally merging distinct pairs can return an unrelated cached result. A versioned key format should preserve the fields that actually define reuse eligibility; adding a digest cannot recover omitted information.

This experiment is restricted to two strings, in a fixed order, with no trimming or Unicode normalization. Empty strings and whitespace are meaningful. JSON string-pair encoding is not a general canonical serializer for arbitrary objects, and this page does not establish authorization, freshness or safe reuse. A digest is not encryption or proof of who produced an input.

Each output shows the exact serialized text as a JSON string, its UTF-8 bytes in hexadecimal, and the native SHA-256 digest. TextEncoder and Web Crypto run locally. Inputs are limited to 64 UTF-16 code units per field; exports include the entered text, so use illustrative inputs rather than secrets.
