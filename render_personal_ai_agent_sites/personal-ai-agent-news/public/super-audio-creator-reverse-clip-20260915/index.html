Reverse time, not polarity

An illustrative use: a creator reverses a short percussive sound so its decay becomes a swell. This tool reverses sample order across the entire decoded clip. It does not negate samples, stretch time, remove silence or apply a fade.

What changes in the exported file?

The browser decodes the complete file and may resample it to the audio context's sample rate. The export is a new 16-bit PCM WAV at that decoded rate, with the same channel count and frame count. Values outside the PCM range are clipped. Lossy input is not restored, and tags, artwork, loop points and original encoding are not retained.

Why can an edge click?

A clip that begins or ends away from zero can produce a discontinuity. Reversing changes which edge comes first. No smoothing is applied here; use an audio editor for precise fades, trimming, multichannel work or longer sessions. Start playback at a comfortable volume.

What stays on this page?

What the cache actually reuses

The public Computer-Use Cache release describes replaying successful responses for exact repeated requests; misses go upstream. A hit avoids another upstream model call, not every execution or infrastructure cost.

Separately, the inspected workflow-cache implementation stores verified-complete, runnable steps with task context. A lookup can return a workflow, helper version and output evidence. Missing context or no safe match returns a miss for the caller to handle. Matching may incur usage. That is implementation evidence, not proof that this audio task is cached in your account, or a measured speed or cost saving.
