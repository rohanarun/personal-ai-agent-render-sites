Human syntax, machine boundary

The example is a fictional preview configuration, not a production deployment file. The conversion keeps its data while removing comments and normalizing syntax. Hexadecimal 0x3 becomes the JSON number 3; quoted labels remain strings.

The JSON5 reference project supports comments, unquoted identifier keys, single-quoted strings and trailing commas. This desk uses its locally bundled version 2.2.3 to parse, then native JSON.stringify to produce strict JSON. It does not evaluate JavaScript expressions or execute configuration.

Know what will not survive

Comments, quote style and numeric spelling are not part of the parsed data. Keep the original JSON5 when those matter. Duplicate property names use the parser's last value; they are not audited here. JavaScript floating-point parsing can round decimal literals before conversion. Store precision-sensitive identifiers and decimals as strings.

This desk rejects non-finite numbers, unsafe integers and negative zero instead of silently converting them into null, rounded integer output or zero. Other decimal rounding can still occur. A valid conversion is not proof that the original numeric text was preserved exactly.

The limit is 100,000 input characters and 50 levels of parsed nesting. Malformed JSON5 and rejected values produce no downloadable result. The tool does not validate your application's schema, resolve environment variables, contact a service or deploy anything. Do not paste secrets.
