Measure instead of assuming

Short input may become larger because a gzip stream has overhead. Repeated text often compresses better than varied text. The byte difference shown here is measured for this exact sample in this browser, not a general savings claim.

The tool uses native CompressionStream with gzip, then DecompressionStream to compare every recovered byte against the UTF-8 input. A successful check enables the download. No compression level is selected, and identical compressed bytes across browser implementations are not promised.

Know the artifact boundary

The download is a single gzip stream containing the textarea's UTF-8 text, not a ZIP archive or a collection of files. Empty text is valid. Pasting can normalize line endings, and UTF-8 encoding can replace isolated surrogate code units. The round trip proves equality with the encoded textarea bytes, not with an original file that was never loaded.

The limit is 100,000 characters. This page does not accept arbitrary compressed files for decompression. It does not validate JSON, configure HTTP Content-Encoding, upload anything, or test a receiving service. A .gz filename alone does not make an endpoint understand the payload.

Compression is not encryption or redaction. Anyone able to decompress the artifact can read the text. Use non-sensitive fixtures; inspect them before sharing. The transformation uses this page's browser APIs without a model call. The product video below loads remote media separately.
