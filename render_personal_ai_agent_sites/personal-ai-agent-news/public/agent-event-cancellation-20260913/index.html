Canceling is not stopping.

A browser agent's interface emits an event. One listener calls preventDefault. Does the next listener still run? Let the native event system show the distinction.

Three distinct mechanisms
preventDefault marks a cancelable event as canceled. It does not stop later listeners. stopPropagation stops propagation along an event path, but does not stop other listeners on the same target. stopImmediatePropagation also prevents subsequent listeners on that target from running.
This experiment has one EventTarget and two listeners, registered in order. It has no parent or child nodes, so it isolates same-target behavior rather than capture and bubbling. Each dispatch creates a fresh target and event; listeners are not passive.
A flag is not an authorization boundary
Illustrative agent UI: a listener marking an event canceled does not undo work already performed by another listener. The code that performs an action must respect the intended contract. Do not treat this flag as a substitute for server-side authorization or proof that an external job was canceled.
The custom event here has no browser default action to suppress. dispatchEvent returns false when the event was canceled, not when a tool failed. No tool, network request, model, or real-world action is executed by this demo.
Read the native contract
The WHATWG DOM Event interface defines cancellation and propagation flags. dispatchEvent defines its return value.
