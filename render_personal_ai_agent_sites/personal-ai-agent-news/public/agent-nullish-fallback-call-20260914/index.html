Nullish coalescing

Defaulting has a predicate

Nullish coalescing chooses the fallback only for null or undefined. Logical OR chooses it for any falsy value. Both short-circuit: when the left operand is retained, the fallback expression is not evaluated.

Enable the throwing fallback with zero selected. OR reaches the throw; nullish coalescing returns zero without calling it. Choose null and both reach the throw. Choose the string "0" and neither calls the fallback: nonempty strings are truthy, regardless of how they look numerically.

Agent configuration needs a contract

In an illustrative retry setting, zero might mean no retries. OR would replace it with the fallback; nullish coalescing would preserve it. But preserving a value is not validating it. NaN also survives nullish coalescing and may still be invalid for a retry count.

This experiment uses a fallback that returns the string DEFAULT, or throws locally. No provider call, retry, payment or tool action occurs. In production, keep configuration validation separate from default selection, and consider whether evaluating a fallback has side effects. Results are exported as tagged values so undefined and NaN do not disappear or become null through ordinary JSON serialization.
