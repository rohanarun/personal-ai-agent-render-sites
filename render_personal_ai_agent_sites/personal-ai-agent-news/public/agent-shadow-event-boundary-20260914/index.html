Shadow Event Boundary Lab

An event can reach a component's internal listener without reaching its surrounding page. Crossing the boundary can also change the target an outside observer sees.

The custom event always has bubbles: true. The shadow root is open.

No event dispatched.

Crossing is explicit

The inner button dispatches a custom event named lab-signal. With composed false, this event remains inside the shadow tree. The surrounding fixture's listener does not receive it, even though bubbles is true. Enable composed and dispatch again: both recorded listeners receive the new event.

These are bubbling listeners only. This fixture does not explore capture or the special host handling of composed events that do not bubble. Nor does it infer every event's defaults from this custom event.

Two observers, different targets

The inside listener sees button#inner as target. The outside listener sees div#host. This retargeting preserves the component boundary; it does not mean two unrelated actions occurred. currentTarget identifies the listener's own node, which differs from target for the outer listener.

The composedPath() snapshot is taken while each listener is running. With an open root, the outside path can include internal nodes. Closed roots filter their internals from an outside observer's path; this lab does not create a closed root.

For browser-agent instrumentation

An observer that only checks event.target on the surrounding page may identify the host, not the internal control. Inspect the component's event contract before interpreting a missing callback or a host target as a failed action. A trace shows delivery, not whether an application saved data or an external tool completed work.

The real click on the button only triggers the experiment. The exported trace is for the synthetic lab-signal event, whose isTrusted is false. It is not a record of a trusted browser click. No model, network request, form submission or external action runs here.

Changing the checkbox clears the previous trace; the next dispatch uses that choice. Reset clears evidence without changing the checkbox. The two bars visualize observed delivery, not timing or success. Only the latest dispatch is exported.
