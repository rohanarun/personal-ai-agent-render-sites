Your pilot shortlist

Start with the operating model

If you must run the workflow runtime yourself, examine the documented self-hosted paths first: n8n, Node-RED, and Windmill. If your team wants configured steps and app connections, compare Make, n8n, Node-RED, Pipedream, Windmill, and Zapier against your actual connectors and governance needs. If the job is delegating actions inside apps, Super is a candidate for a bounded pilot, not an automatic substitute for an integration platform.

The matrix deliberately uses narrow definitions. Self-hosting means the workflow runtime, not a local agent connected to a hosted service. A configured-step builder means authoring a workflow from explicit steps, not merely asking a conversational assistant to do work. The assistant criterion means a first-party hosted assistant offering that operates its apps and browsers; it does not score all possible third-party browser integrations.

Compare complete costs

Different billing units are not interchangeable. n8n lists workflow-execution plans. Make uses credits, with some AI features consuming more than one. Zapier uses task allowances and variable usage rates for some actions. Super lists wallet usage and optional managed-device plans. For self-hosted software, include hosting, upgrades, monitoring, and staff time. No monthly total is estimated here.

For each shortlisted option, record a representative input, exact output, expected frequency, required access, retry behavior, and human approval point. Confirm current plan limits and obtain a quote where the public page does not settle your requirements. A documented capability is not a reliability, privacy, or compliance guarantee.

Where Super's cache fits

The first-party release describes a response cache: successful responses are reused for exact repeated requests; misses go to the upstream model provider. A cache hit avoids that repeated model call, while execution and infrastructure can still cost money.

A separate local workflow-cache implementation inspected for this page stores verified completed workflows with runnable Python steps and task context. Storage can be declined by portability checks. Lookup returns a workflow with verification evidence or a miss when context or a safe match is absent. Matching may itself incur usage; the caller is responsible for handling a miss.

Response reuse and workflow reuse are different mechanisms. Their implementation does not establish availability for every account, compatibility with every app, or measured savings for your workload. Cache reuse cannot replace fresh authorization or verification of the final result. None of this comparison's other vendors has been tested for equivalent or competing cache behavior.

Keep the first experiment small

Use non-sensitive sample data. Check one successful run, one rejected input, and one interrupted operation. Save the final artifact and observed cost before expanding the workflow.
