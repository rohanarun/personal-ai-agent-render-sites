Task IDs are not a queue.

Insert keys into an ordinary object, then ask the browser for its keys. A task named "2" may appear before "10" even when it arrived later. Observe the rule before using object enumeration as an execution schedule.

Two groups, not one arrival list
For ordinary objects, own array-index keys are ordered numerically first. Other string keys follow their creation order. The string "01" is not an array index in the same way "1" is. Try moving both to the beginning and compare the result.
This experiment creates enumerable own properties on an object with a null prototype. Values record insertion positions. Object.keys runs natively; the page does not sort the result itself. Duplicates are rejected so overwriting a property cannot obscure the experiment.
An agent pipeline consequence
Illustrative scenario: completed jobs are stored under numeric-looking IDs. Enumerating that object does not recover completion chronology. Store the chronology explicitly in an array of event records when order matters. An ID is an identifier, not a timestamp or priority.
This lesson covers string keys on ordinary objects only. Symbols, inherited properties, non-enumerable properties, deletion and reinsertion, and proxies are outside its input model. Do not generalize this trace to every property-enumeration API.
