The invisible config override

An object can own a property whose value is undefined. That property still replaces a default during spread, then disappears from its JSON representation.

One round trip changes the merge

const defaults = { retries: 3 };
const merged = { ...defaults, ...override };
const json = JSON.stringify(merged);
const parsed = JSON.parse(json);
const mergedAgain = { ...defaults, ...parsed };

When the override owns retries with value undefined, merged owns it too. JSON.stringify omits that object property. The parsed object therefore lacks it, and applying the defaults again restores 3. Null and zero survive this round trip.

Three is an illustrative value, not a recommended retry count. These operations do not validate configuration or execute retries. The lesson concerns ordinary enumerable own properties in plain objects, not getters, inherited properties or custom serialization.

Make absence part of the contract

Define whether missing, undefined, null and zero mean different things before merging agent settings. Inspect property presence separately from value. A JSON log alone cannot distinguish a missing property from an undefined property that was omitted.

Choose validation and serialization rules for the receiving system. Do not assume null means disabled, zero means unlimited, or an absent field means safe. This experiment demonstrates behavior, not a universal configuration policy.
