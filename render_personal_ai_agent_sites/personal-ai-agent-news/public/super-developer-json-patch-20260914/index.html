An ordered edit, not a merge

JSON Patch is an ordered list of operations. The example tests the current environment, replaces a retry count, then appends a step with the /steps/- path. A failed test stops processing. Removing an array entry changes later indices; inspect operation order carefully.

Paths use JSON Pointer notation. A slash inside a key is escaped as ~1; a tilde is escaped as ~0. This is not a dotted-property path. Add, remove, replace, move, copy and test are handled by the library. A test checks this local input, not whether a remote document has remained unchanged.

What gets exported

The desk uses vendored fast-json-patch 3.1.1 with operation validation enabled, original-document mutation disabled and prototype modifications banned. Each preview starts from the current source text. If an operation fails, no partial result is offered for download and the source textarea stays untouched.

Download contains only the final JSON document, not the patch, a rollback or an HTTP request. Editing either input invalidates the old result. Application schema, permissions, concurrent edits and deployment safety must be checked separately.

Super and reviewed changes

Super Powers AI supports app, browser and code work. Its inspected computer-use cache stores verified workflows with runnable steps. A hit returns the procedure with helper-version information and output evidence: actual execution infrastructure rather than only reusable prose.

Lookup requires an owner and task or source context. Missing context, no entries or no safe match produces a miss; a caller must handle that separately. Saving requires verified-complete confirmation and runnable steps. Matching can incur usage charges. A cached workflow does not prove a new patch is correct or that its next execution succeeded.

Use a sanitized example when asking for help preparing a patch. Review the proposed operations and the resulting document, then test against the actual application's schema. This page never calls Super or modifies a repository, server or account.

Parsing limits

Each input is limited to 50,000 characters, patches to 100 operations and nesting to 40 levels. Native JSON parsing retains the last duplicate key and may round numeric literals. Non-finite numbers, unsafe integers and negative zero are rejected; use strings for exact quantities and identifiers. Original whitespace is not preserved.
