Live queue or snapshot?

An agent's task list can change between iteration steps. A live array iterator follows positions, not the identity of the task that used to occupy them.

Both iterators start at index zero.

Native array values() iterators. The snapshot is a slice taken at restart. These are task labels only; nothing is executed or sent to a model.
Make a task disappear from the visit order
Advance once to visit "fetch". Remove the first live entry. The live iterator's next position remains 1, now occupied by "send", so "review" is skipped. The snapshot still returns "review".
Append before or after completion
A live array iterator reads the current length on each next call and can visit appended entries. Once it returns done, it stays done even if the array later grows. Merely yielding the last element is not yet the same as returning done.
Our snapshot holds strings in a separate array. A shallow snapshot of objects would still share those objects; this is not isolation for their internal fields.

Before using this in an agent
Choose whether newly arriving work belongs in this pass or a later one. Removing array entries is not an acknowledgement protocol. This experiment does not provide persistence, retries or exactly-once execution.
