Read-Only Does Not Travel

A wrapper copies an agent's configuration. The value survives, but does its read-only rule? Inspect native property descriptors and attempt the same write on the source and its copy.

Values and descriptors are different things
What starts protected?
The source has a data property maxSteps: 3 with writable false, configurable false, and enumerable true. Its second property, origin: "illustrative-source", is also read-only but non-enumerable. The source is an ordinary extensible object, not a deeply frozen object or security boundary.
Why do spread and assign accept the write?
In these examples, object spread and Object.assign({}, source) copy enumerable own values into a fresh ordinary object. The new maxSteps property is writable and configurable. The non-enumerable origin property is omitted. The original property remains unchanged.
These are observations for this data-only source and fresh empty target. Object.assign can interact with target setters, and copying accessors has additional semantics not exercised here.
What does the descriptor copy preserve?
Object.create(Object.getPrototypeOf(source), Object.getOwnPropertyDescriptors(source)) creates a shallow copy with the source's own descriptors. Here it preserves both properties and their flags, so attempts to change maxSteps fail on both objects.
This is not a general deep clone. It does not recursively protect nested objects or reproduce every internal slot of built-in objects. Copying descriptors also does not automatically reproduce a source object's extensibility state.
What does a failed write mean?
The experiment uses Reflect.set, whose boolean result reports whether this write succeeded. A false result is visible without relying on silent non-strict assignment or a strict-mode TypeError. Agent code must validate its actual configuration at the consuming boundary; a read-only property on some earlier object is not enough.
Inspect the handoff, not just the source
Try spread with 9, then switch to the descriptor copy and repeat. The values initially look identical; their behavior differs. The export includes descriptors, current values, the copy expression, and each native write result.
