Validate before information disappears

These three fields stand in for a tool's score, duration, and optional result. The unguarded path demonstrates transport behavior, not a recommended tool contract. A receiver cannot infer the original state from a bare null.

Why a successful export is not a valid result

Native JSON serialization maps NaN, positive infinity, and negative infinity to null. An original null also remains null. This applies to the object properties and array elements in this experiment; no field is omitted. Parsing the text does not restore the lost distinctions. JSON.stringify reference.

What the guard does, and does not, promise

The guard inspects the three original values. It rejects a numeric value when Number.isFinite returns false; it deliberately permits null because this example allows an empty result. A real tool may require a finite number instead, plus units, bounds, and field-specific constraints. Number.isFinite reference.

This flat-record check is not a general recursive validator. It does not cover nested objects, getters, custom toJSON methods, cycles, or other JavaScript types. Rejecting an invalid record here produces no wire payload.

When a nonfinite state is meaningful

Define an explicit agreed schema such as a status field with a reason and a separate finite value. Do not silently replace an infinity with a large number or label every null a calculation failure. The evidence download uses typed text labels for the original values so the diagnostic file does not repeat the same loss. Those labels are a report format, not a universal decoder.

Check the input boundary too

A finite-value check can also coerce a string or an empty value if you choose the wrong function. Explore that separate failure at the finite input types workbench.
