Make recovery explicit

Reliable agents separate transport uncertainty from business state before they repeat an action.

Confirm before replay

Read the operation status or use an idempotency key when a timeout leaves the side effect ambiguous.

Bound the retry

Keep retries finite and observable so a transient failure cannot become an infinite duplicate loop.

Stop with state

When replay safety is weak, preserve the request and surface a clear recovery step instead of guessing.

This simulation is a teaching model, not a production retry policy. It demonstrates a contract-first pattern: detect ambiguity, check replay safety, and bound recovery.
