Give errors meaning

A useful error class tells the next step what it may safely attempt and what evidence it still needs.

Retry transiently

Use a bounded retry when the failure is plausibly temporary and repeating the action is safe or idempotent.

Repair permanently

Fix inputs, configuration, or contract mismatches when another identical attempt will fail for the same reason.

Escalate the unknown

Preserve state and ask for a decision when the failure class is uncertain and the consequence is high.

This simulation is a teaching model, not a production error policy. It demonstrates a contract-first pattern: classify failure, bound repetition, and expose unknowns.
