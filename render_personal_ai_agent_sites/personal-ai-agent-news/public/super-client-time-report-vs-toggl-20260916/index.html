A finished deliverable is not a timesheet

You revised a landing page and sent the client a preview. The task is visible, but its duration is not. A two-hour estimate, a two-hour calendar reservation and a two-hour recorded entry are different kinds of evidence. A writing assistant should not silently turn one into another.

Start a progress report with three separate facts: the delivered outcome and its evidence, the time record if one exists, and the next unresolved action. If time is missing, say so. Do not infer duration from the number of files, messages or paragraphs produced.

A repeatable Friday handoff
  1. Close the reporting window. Set the client, project, dates and time zone. Resolve running timers and obvious duplicate entries with the person who owns the records.
  2. Reconcile outcome and time separately. A preview link supports a delivery claim, not a duration. A time entry supports a reported duration, not client acceptance.
  3. Give the draft clear boundaries. Ask for a short outcome summary, unresolved items and next steps. Preserve missing records and estimate labels. Never fill gaps with plausible hours.
  4. Review before sending. Compare every duration with the original export and every completion claim with its evidence. A report is not an invoice or authorization to charge.
Prerequisites: access to the relevant records, permission to share them, and a named reviewer. Remove unrelated clients and sensitive descriptions from any export. If your existing Toggl report answers the client's question, send that through your normal approved process instead of adding another tool.

Cached responses are not time records
The computer-use cache has public implementation code. The pinned server normalizes requests, looks up stored responses and avoids the upstream model call on a hit. Misses go upstream; eligible JSON responses can be saved. It includes expiry and bypass controls, and ignores metadata by default.
That reuse does not prove anyone worked for a particular duration. A cached draft can also reflect an old export. Include the current source content in the task and review the output against it; use freshness controls where appropriate. Other service costs remain, and public source code does not verify every production configuration.


Keep the log authoritative
Use Toggl for the time record when that is your need. Evaluate Super for the surrounding research and narrative, not for reconstructing missing hours. Keep estimates visibly separate until a responsible person reconciles them.
