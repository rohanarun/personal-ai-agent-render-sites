Empty Validation Lab

“Every check passed” and “checks were performed” are different claims.

    Native predicate result

    Start with no evidence
    The initial list is empty. The browser's native every() call returns true without invoking the callback. It found no counterexample; it did not establish that an artifact exists.
    Add a pass, then a failure, then another pass. every() stops at the first failure. The callback index list exposes that short circuit: a result stored later in the array may never be visited by this particular predicate.
    Clear the list again. A separate nonempty condition changes the illustrative gate, but nonempty alone cannot prove you collected the right checks or all required checks.
    Apply this to an agent pipeline
    Filtering a tool-result list can accidentally leave no entries. A universal predicate over that list still returns true. Validate collection completeness against the task's required evidence before interpreting the aggregate result.
    The example gate is results.length > 0 && results.every(isPass). It is shown for contrast, not as a production authorization rule. Real policies may need expected identifiers, freshness, provenance, and explicit handling of missing or pending results.
    These are user-entered illustrative labels. No tool ran, no files were inspected, and no model was called. Exported marks are not verification receipts.
