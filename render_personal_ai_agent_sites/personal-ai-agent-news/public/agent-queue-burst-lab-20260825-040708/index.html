Make pressure visible

Backpressure is useful when it protects work and tells the next agent what happened.

Bound concurrency

Limit in-flight calls so one burst cannot consume every tool slot or turn latency into a cascade.

Keep per-item state

Track accepted, delayed, failed, and dropped work separately so a batch does not hide individual outcomes.

Shed deliberately

When failure cost is high, reject or defer with a reason instead of launching retries that will fail together.

This simulation is a teaching model, not a production load policy. It demonstrates a contract-first pattern: bound concurrency, preserve outcome state, and make backpressure explicit.
