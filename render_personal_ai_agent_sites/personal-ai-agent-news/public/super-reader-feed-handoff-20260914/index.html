Subscriptions, not saved articles

OPML 2.0 can exchange subscription lists. This export contains a head, a body, and one rss outline per feed with text, title and xmlUrl attributes. It is deliberately flat: folders, read state, downloaded articles and app-specific settings are not included.

Enter a feed endpoint, not just a site's homepage. This desk only checks for an absolute HTTP or HTTPS URL without embedded credentials or a fragment. It normalizes the address with the browser URL parser and rejects exact normalized duplicates. It does not fetch the destination, verify RSS content, or confirm a reader can import it. Distinct URLs may still point to the same feed.

Labels and addresses are serialized using the browser XML APIs, so quotes and ampersands become valid XML attribute content. Invalid XML characters are rejected. The illustrative example uses reserved example.org addresses, not working feeds; replace them before a real import. There is no account connection or persistent storage here.

Check the receiving side

Before moving a large collection, export two real public feeds and test the receiving app's OPML import. Check the resulting labels, subscription count, and whether new items appear. Keep the previous reader until that check succeeds. An accepted file is not proof that every subscription works.

A subscription address can contain a private access token even without a username and password. Review every address before sharing this file; URL-format validation is not a secret detector. No subscription is created or removed by this page. The download contains the saved list, not an unfinished edit in the form.
