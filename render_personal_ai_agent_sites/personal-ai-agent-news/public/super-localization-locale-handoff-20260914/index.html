Canonical does not mean supported

EN-us becomes en-US. That is normalization of an identifier, not proof that your product has an English translation for the United States. This tool uses Intl.getCanonicalLocales for structural validation, and preserves a row for every input even when two inputs normalize to the same tag.

Underscores are not silently changed to hyphens: EN_US is rejected by this API. Fix invalid rows before export. The canonical list in the JSON removes duplicates in first-occurrence order; the detailed rows preserve the original trimmed values and identify repeated canonical tags.

Likely subtags are inferred, not chosen

Intl.Locale.maximize adds likely language, script or region information using the browser's locale data. Minimize removes subtags that can be inferred again. These operations do not reveal a person's location or preferences and do not select the right market for a translation.

Keep explicit product requirements separate from inferred defaults. Browser locale data can differ by runtime version. This report is a local runtime observation, not a universal registry audit, translation coverage test or fallback-routing policy.
