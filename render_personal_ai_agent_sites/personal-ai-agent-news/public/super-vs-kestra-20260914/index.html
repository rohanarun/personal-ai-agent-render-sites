What is implemented in Super

The inspected computer-use cache store route requires verified-complete confirmation, task or source context, and runnable Python workflow steps. Lookup requires an owner and can return a matched procedure with a helper-version hash, verification reason and output evidence. This is actual procedure storage and retrieval, not just repeated answer text.

No context, no entries or no safe match returns a cache miss. The caller must handle that miss separately; this endpoint alone does not prove a particular fallback experience. Matching may incur usage charges. Reusing an eligible procedure can avoid reconstructing that procedure, but it does not imply the current external task is already complete.

Consider Super when the need is assistant-driven work through computer surfaces. Confirm the specific workflow, account access and completion evidence first. The inspected implementation and first-party video do not establish universal compatibility, live availability for every account, or measured savings. Product and current access options.

Do not buy on a cache label alone

An illustrative catalog pipeline may need an old download reused for an agreed period; a repeated browser task may instead need actions performed again against current state. Those are different requirements. Ask each vendor what expires, what gets re-executed, and how an incorrect reuse is detected.
