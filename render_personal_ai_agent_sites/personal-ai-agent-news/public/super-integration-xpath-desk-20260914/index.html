Match the result type to the task

The example selects the id attribute of ready jobs. Try count(/jobs/job) for a number, boolean(/jobs/job[@state='ready']) for a boolean, or string(/jobs/job[1]) for text. An empty node selection is a valid result, not a parser failure.

The browser evaluates XPath against the parsed XML document. Prefixes in the expression are resolved using declarations on the root element. Unprefixed names select no-namespace elements; a default XML namespace does not automatically become the XPath default. Add a named prefix declaration to the root and use that prefix in the expression when needed.

A selector needs more than one passing sample

Illustrative test plan: check an empty collection, multiple ready jobs, a changed namespace and missing attributes. A selector that works once may still encode an accidental assumption. This desk does not validate a schema or prove that the selected node is the right business record.

Node results are serialized as text, never inserted as live markup. The exported JSON includes the expression and result, but not the complete XML source. Selected values may still contain sensitive data; use sanitized samples. Non-finite numeric results are represented explicitly as strings with a finite=false marker.
