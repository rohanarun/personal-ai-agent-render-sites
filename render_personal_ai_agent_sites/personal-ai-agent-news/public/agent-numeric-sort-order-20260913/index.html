Why 100 comes before 2

Without a comparator, ordinary Array.sort compares string representations. In the example, "100" starts with "1", while "2" starts with "2". Numeric ascending order instead uses (a, b) => a - b; descending uses (a, b) => b - a.

The return value of the comparator supplies an ordering sign, not a score to keep. A negative result places a before b, a positive result places b before a, and zero treats their sort order as equal. This page restricts input to finite numbers so invalid-value policies do not obscure that distinction.

Ordering and ownership are separate choices

Array.sort changes its receiver and returns that same array. Checking "Sort a copy" uses [...source].sort(...), so this example's source retains its order. The copy is shallow; this page contains only primitive numbers, not nested objects.

Illustrative agent scenario: a tool returns relevance scores in a list. First decide whether higher or lower scores are better, then choose numeric ordering. Preserve the source if another consumer needs its original order. Correct sorting does not establish that the scores measure relevance or that the highest-scoring result is trustworthy.

Every run reparses the input. The result is a browser observation, not a model evaluation or performance benchmark. The internal sorting algorithm and comparator-call count are intentionally not assumed.
