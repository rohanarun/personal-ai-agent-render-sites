    A receipt for bytes, not a signature

    This manifest records each selected file's name, byte length and SHA-256 digest. It reads the original bytes without text conversion or normalization. The same content under a different name keeps its digest, but changes the manifest's name field. A zero-byte file is valid.

    Compare against a trusted expected manifest. A hash alone does not identify the author, prove a file is safe, or confirm that a server deployed it. An attacker able to replace both the file and its manifest can replace both consistently.

    Developer handoff checklist

    Freeze the release files first. Save this JSON alongside the approved release record. After transfer, hash the received files and compare names, sizes and digests. Investigate missing, additional or changed files before approval. This page creates a manifest; it does not automatically perform that comparison or publish the release.

    Selection order is retained. Paths and modification times are omitted, so two files with the same base name are rejected. A new selection replaces the complete batch only after every digest succeeds; an invalid batch leaves the last completed manifest intact. This is a small-file workbench, not a streaming archive verifier.
