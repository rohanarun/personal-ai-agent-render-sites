Short codes need long partners

A fixed-width code for four symbols uses two bits per symbol. Huffman coding repeatedly combines the two lowest-weight nodes, building a binary tree with minimum expected code length among binary symbol-by-symbol prefix codes for the given distribution. Ties can produce different, equally good codebooks.

With counts 8, 4, 2, 1, the code lengths are 1, 2, 3, 3. The expected cost is (8 + 8 + 6 + 3) / 15 = 1.667 bits per symbol. This expectation uses the codebook frequencies, not the composition of your particular message.

A smaller expectation is not a smaller file

A message full of rare symbols can take more bits than the fixed-width baseline. These totals count payload bits only: a real file also needs a shared or transmitted codebook, framing, and byte padding. The displayed bit string and exported JSON are teaching representations, not bit-packed compressed files.

Probability models matter in machine learning and compression, but this is not an LLM tokenizer or neural compressor. It uses a fixed four-symbol alphabet, assumes symbol-wise frequencies, and ignores sequential context. All counts are illustrative.
