The experiment

Each run creates a new EventTarget and one named listener. The outer callback dispatches a new event with the same type. A depth guard allows exactly one nested dispatch, preventing unbounded recursion in the late-removal fixture. After the outer dispatch returns, another event tests whether the listener remains.

target.addEventListener('complete', handler,
  { once: policy === 'once' });
target.dispatchEvent(new Event('complete'));
target.dispatchEvent(new Event('complete'));

Read the call order

The DOM event invocation algorithm removes a once listener before calling it. The nested event therefore does not find that listener. With removal at the end, the outer invocation has not removed it yet, so the nested dispatch can enter it again.

The final probe adds no callback in either mode: by then the listener has been removed. Equal behavior on the next ordinary event does not imply equal behavior during a nested dispatch. See the addEventListener options reference.

Agent-controller consequence

A local controller might use an event to hand off a completed step. If callback work emits another event synchronously, removing the callback only after that work is not equivalent to a one-time listener. The trace here measures actual browser callbacks, not modeled probabilities.

This does not provide durable exactly-once processing, idempotent tool calls or distributed delivery guarantees. A once listener is consumed when invoked, not when its work successfully commits. This fixture performs no external action and contains no asynchronous task or LLM.
