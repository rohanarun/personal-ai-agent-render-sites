Visible is not submitted

An agent can see a field on screen without that field appearing in a form's entry list. Compare the real controls with the browser's FormData output.

Native entry list

Constructed with new FormData(form). The form never submits; no network or model call occurs. Experiment settings sit outside the form.
Three useful distinctions
Disabling task excludes it from this entry list. Making it read-only leaves it included. If both settings apply, disabled still excludes it.
An unchecked include_sources checkbox contributes no pair, not a false string. Removing note's name excludes it even though its text remains visible. An enabled named text field with an empty value contributes an empty string.
Agent handoff example
Illustrative workflow: a browser agent fills a draft form, then another component serializes it. A screenshot confirms visible values but cannot prove which entries the browser constructed. Inspect the actual payload and the destination's schema before interpreting an absent value as a deliberate choice.
This does not mean an agent should override disabled controls. They can represent real application constraints. Determine why a field is disabled and use the intended workflow.
What the lab leaves out
No submitter is passed to FormData, and there are no file inputs, fieldsets or custom form controls. Constructing FormData does not itself run constraint validation or grant authorization. The export is an ordered list of text pairs, not a server request or proof of successful processing.
