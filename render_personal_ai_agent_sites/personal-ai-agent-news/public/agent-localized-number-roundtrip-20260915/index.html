Three different contracts
A formatter is not an inverse parser
Intl.NumberFormat produces locale-sensitive display text. Grouping, decimal marks, digits, and rounding depend on its options. The part strip comes from formatToParts(); it exposes the actual separators rather than guessing from their appearance.
A partial parse can look successful
parseFloat consumes a valid numeric prefix and stops at the first unsupported character. It is not locale-aware. A comma or a narrow non-breaking space can end the parse. Number requires the whole string to be convertible, so the same display often becomes NaN instead. Neither result should be treated as validated tool input.
Even punctuation-free text can lose information
Turn grouping off and reduce fraction digits. The display can round the source before parsing even starts. Removing separators is not a general repair: a decimal comma and a grouping comma have different roles.
Agent handoff rule
Keep the original numeric value in a typed, validated payload; format a separate display string for people. If only localized text is available, require an explicit locale and a suitable parsing contract before acting. This experiment uses finite numbers within ±1 billion, excludes negative zero, and compares against the JavaScript Number already obtained from JSON. It does not solve exact decimal arithmetic or precision loss that happened before that point.
Try the boundary
With 1234.5, compare English, German, and French displays. Then disable grouping in English: the parse can match again. Finally set zero fraction digits and watch rounding break the round trip without a separator involved.
Native browser behavior, not a model simulation. Evidence exports represent non-finite parser results as labeled strings so JSON does not silently turn NaN into null.
