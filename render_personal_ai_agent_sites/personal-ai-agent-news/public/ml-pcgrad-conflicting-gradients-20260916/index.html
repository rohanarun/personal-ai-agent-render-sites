When task gradients disagree

One shared model, two losses. A step that helps one task can hurt another. Removing the conflicting component changes the direction, but does not promise a better trained model.

Project the conflict, not the whole task away
For original gradients a and b, conflict means a dot b < 0. Two-task PCGrad then uses:
a' = a - [(a dot b) / (b dot b)] b
b' = b - [(a dot b) / (a dot a)] a
p = a' + b';   parameter step = -eta p
Both projections use the original other gradient. If the dot product is nonnegative, both stay unchanged. With more tasks, the paper processes other tasks in randomized order; this experiment covers only two. See Yu et al., Algorithm 1.


A concrete trade-off
Set B to (-2, 1, 0). The raw sum is (-1, 1, 0): descending along it increases A's loss to first order. Projection gives a' = (0.2, 0.4, 0), b' = (0, 1, 0), and p = (0.2, 1.4, 0). The directional loss changes become -0.2 for A and -1 for B. The raw changes were +1 and -3. Protecting A here sacrifices some immediate progress on B.
This is a local calculation: for a smooth loss, L(theta - eta p) = L(theta) - eta (g dot p) + O(eta squared). Curvature and a large step can overturn the first-order prediction.


Exactly opposed is a warning, not a win
The opposed example sets B = (-2, 0, 0). Each projection is zero, so PCGrad stalls even though the raw sum is nonzero. Neither task's gradient vanished. The tasks disagree along the same axis; eliminating both opposing components leaves nothing.
Why both two-task directional derivatives are nonpositive
In the conflict branch, a dot b' = 0. Consequently a dot p = ||a|| squared - (a dot b) squared / ||b|| squared, which is nonnegative by Cauchy-Schwarz. The same argument holds for b. Negating p gives nonpositive directional derivatives. Equality is possible, including opposite collinear vectors. This statement is local and specific to the two-task construction.
What this experiment leaves out
There is no dataset, optimizer momentum, stochastic minibatch noise or fitted loss surface here. These adjustable vectors represent gradients at one parameter point. A zero B has no conflict and requires no division. Real systems also need consistent shared-parameter layouts and numerical handling for tiny norms.
The authors' implementation flattens per-task gradients, projects them, sums the corrected values and passes them to an optimizer. Our geometric calculation uses Three.js Vector3 projection; no neural network is trained in this page.
