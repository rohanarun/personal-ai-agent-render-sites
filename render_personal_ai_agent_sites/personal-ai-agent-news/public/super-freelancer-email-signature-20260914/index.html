The example identity is fictional. Name, role and studio allow up to 80 characters each; email up to 254 and website up to 2,048. Outer whitespace is trimmed, optional empty lines disappear, and website URLs are normalized by the browser. The preview's links do not navigate; exported links remain active.
Keep the email-client boundary explicit
The HTML file contains a simple inline-styled signature fragment. Email clients differ in how they import, paste, sanitize and display signatures. This is a browser preview, not proof of rendering in Gmail, Outlook or Apple Mail. Review an actual draft and send yourself a test before using it with clients. The plain-text file is the fallback when rich formatting is unavailable.
Text remains text
Names and labels are inserted with DOM textContent, not interpreted as HTML. The exported HTML is serialized from those DOM nodes. Website links accept only HTTP or HTTPS without embedded credentials. Email validation checks browser-supported syntax, not mailbox ownership or deliverability. No message is sent.
The form builds exports locally without model calls or form uploads. This page loads a remote product video; that is separate from the form. It does not connect to your inbox, change signature settings or persist your draft after reload.
