Timeout is not cancellation

A caller can stop waiting while a tool keeps working. Watch both states, not just the first result.

Two separate lifetimes
The caller uses Promise.race between the tool promise and a rejecting timeout. That settles the caller's result, not the losing operation. With cancellation off and the longer delay, the caller reports a timeout, then the tool still records completion.
With cancellation on, this lab explicitly calls AbortController.abort after the timeout. The tool has an abort listener that clears its timer and rejects its promise. That cooperative cleanup is separate code, not something Promise.race does. With the shorter delay, the tool wins and the unused timeout timer is cleared.
Why this matters for agents
Illustrative scenario: a tool submits a report while its caller has a shorter deadline. A timeout message alone does not establish whether submission occurred. Retrying an uncertain external action can repeat it. A real integration needs its own operation-status and retry contract; this timer lab neither submits a report nor proves any service can cancel an action.
Cancellation cannot reverse an already completed effect. An API that ignores the signal will not acquire cancellation support merely because its caller creates a controller. Separate the waiting deadline, cancellation request, and evidence of the operation's outcome.
Read the evidence
The trace records elapsed browser time using performance.now. Timer delays are requested delays, not timing guarantees; busy or background tabs may run callbacks later. The bars show categorical state, not elapsed-time magnitude. Controls remain locked until the tool settles, so a second run cannot silently replace work still in progress.
Export includes settings, caller result, tool result and all observed events. This demonstrates JavaScript behavior rather than model reasoning, production latency or network cancellation. MDN Promise.race documents first settlement and the absence of automatic cancellation. MDN AbortSignal explains abort-aware operations.
