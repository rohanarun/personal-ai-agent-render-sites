Settlement order
    Buttons resolve or reject local promises. No agent, network request, timer or external tool is running.
    Rejection is not cancellation
    Reject Tool B first. Promise.all rejects while A and C remain pending. You can still fulfill them. Nothing in this experiment cancels those promises or reverses their effects.
    Completion order is not input order
    Reset and fulfill C, then A, then B. Both final arrays retain the original A, B, C input order, even though the event log records a different settlement order.
    Choose the result contract
    Illustrative agent design: all three lookups may be required for a combined answer, or each lookup may be independently useful. Promise.all exposes the first observed rejection; allSettled waits for every input to settle and includes each outcome. Neither decides whether the result is correct or useful.
    A permanently pending input keeps allSettled pending. Time limits, cancellation, retries and compensation are separate policies. Reset here creates a new experiment and ignores callbacks from the previous one; it is not a production cancellation mechanism.
