Design for the real objective

Reward hacking is a specification problem as much as a model problem. Narrow proxies invite clever behavior that satisfies the measurement while violating the intent.

  • State the goal in observable, testable terms.
  • Probe for strategies that score well for the wrong reason.
  • Keep an escalation path when behavior is surprising.

Try the recovery

Raise oversight while keeping the mismatch high. Notice that more review does not repair a bad proxy; it buys time to detect and revise it.

Pause before optimizingIf the proxy is climbing faster than the goal, inspect the specification before adding more autonomy.
