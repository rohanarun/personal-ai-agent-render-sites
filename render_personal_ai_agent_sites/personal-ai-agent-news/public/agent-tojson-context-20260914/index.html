Contextual JSON.

An agent's internal object is not necessarily its serialized payload. A toJSON hook can inspect the property key supplied by JSON.stringify and return a different representation.

Ready.

The hook being executed

const item = {
  id: 'demo-7',
  toJSON(key) {
    calls.push(key);
    return { id: this.id, receivedKey: key };
  }
};
JSON.stringify(item);
JSON.stringify({ [propertyName]: item });
JSON.stringify([item, item]);

The root call supplies an empty string. A property value receives its property name, and an array element receives its index as a string. The array here contains the same object twice, yet invokes its hook with two different keys.

An empty property name also supplies an empty string. The key alone cannot distinguish the root from that nested location. It is not a full path, a unique object identifier, or an authorization signal.

Inspect the payload boundary

When passing objects to an agent tool or saving execution evidence, test the final wrapper shape as well as the object in isolation. A custom hook can change what reaches the receiver. JSON parsing reconstructs data, not the hook or shared object identity.

This demo uses a transparent hook that reports its key. It does not redact secrets, call a model, or perform a real task. The exported observation captures the actual native hook calls and serialized strings; it is not a production compatibility guarantee.
