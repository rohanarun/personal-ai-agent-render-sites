Preserving the day can leave the month
Start at January 31, 2025 and advance once. The call requests month index 1, February, while keeping day 31. The native result is March 3. Move back once and the retained day is now 3, yielding February 3 rather than January 31.
The browser is normalizing, not clamping
setUTCMonth changes the Date object in place. Without a day argument, it uses the current UTC day of month. Out-of-range components normalize into another month or year. Its return value is the new timestamp. Native method reference.
Specify the recurrence separately
For an agent scheduler, decide whether a missing day means the month's final day, a skipped occurrence, or another explicit rule. Preserve the original intended day separately from the last executed date. Repeatedly mutating the last result can carry earlier normalization into future runs. None of these policies is implemented by the month buttons here.
UTC is an experimental boundary
This experiment fixes midnight UTC and uses only UTC getters and setters. It does not model local time zones, daylight-saving changes, business days, leap seconds, calendar permissions, or delivery reliability. No reminder is scheduled and no external account is connected.
The starting date must be valid and between 1900 and 2100. This bounded rehearsal allows twelve mutations per loaded date. A change to the starting-date field pauses mutations and export until that date is loaded, so the visible draft cannot be confused with the active trace.
