The object is the cursor

A generator object is both iterable and an iterator. Its iterator method returns itself, so another spread does not create a fresh cursor. Calling the generator function again creates a different object. The array's iterator method creates a new iterator for each pass.

Taking one item from the shared generator consumes it. The next full pass gets only the remaining jobs; a later pass gets none. An empty result is ordinary completion here, not an exception. This differs from breaking early and triggering iterator closing.

Retry the right thing

In an illustrative adapter, a logging pass might accidentally consume the same generator later handed to a worker. Retaining a factory or deliberately materializing a finite sequence can make a second traversal possible. Neither makes external actions idempotent. Replaying jobs may repeat side effects, and a fresh source may return different data in a real system.

This experiment uses fixed local strings, native generators and array spread. It performs no actual fetch, review or send operation. Duplicate labels are retained. Input accepts one to six nonblank lines, each up to 48 characters after trimming. Editing pauses operations and exports until Apply restarts all state.

The history is bounded to 12 operations per restart. A take after completion records done:true with no value. Exports retain each pass separately; they are observations, not durable acknowledgements or exactly-once processing guarantees.
