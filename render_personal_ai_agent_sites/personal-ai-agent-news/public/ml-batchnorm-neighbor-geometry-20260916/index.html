Centering removes one direction

For this one-channel batch x = (1, 2, t), take the arithmetic mean across the three examples. Subtracting it makes the centered coordinates sum to zero. In three dimensions, that is a plane through the origin, perpendicular to (1, 1, 1). Division by one shared positive scale leaves the point in that plane.

mu = (1 + 2 + t) / 3 v = [(1-mu)^2 + (2-mu)^2 + (t-mu)^2] / 3 zi = (xi-mu) / sqrt(v + epsilon) z1 + z2 + z3 = 0 ||z||^2 = 3v / (v + epsilon)

The pink ring is the intersection of this plane with the radius-sqrt(3) sphere. With positive epsilon, the green point lies inside it, not exactly on it. Increasing epsilon shrinks the normalized batch toward the origin. Here v is always positive because the first two inputs differ.

This is an exact geometric consequence of the displayed equations, not a claim that a neural network learns on a literal three-dimensional sphere. With N examples the analogous centered subspace has dimension N-1.

Three experiments worth trying

Start at t = 3

The mean is 2 and variance is 2/3. With tiny epsilon, the outputs are approximately (-1.225, 0, 1.225). The middle example is exactly at the batch mean.

Move t to -4

The first input is still 1, but its training output becomes positive: the new mean is -1/3. The example changed relative to its neighbors, not in isolation.

Raise epsilon to 1

At t = 3 the squared radius becomes 1.2, rather than almost 3. The zero sum survives, but unit batch variance does not. Epsilon is not merely cosmetic when it is large relative to v.

Evaluation is a different calculation

The last column uses deliberately fixed statistics: running mean 0 and running variance 1. Its output is xi / sqrt(1 + epsilon). Consequently its first two outputs do not change as t moves. These are illustrative statistics, not running estimates learned from this experiment.

PyTorch BatchNorm1d normally uses batch statistics for the training forward pass and tracked running statistics in evaluation. The forward variance uses the biased estimator; the running variance update uses an unbiased estimator. If tracking is disabled, evaluation also uses batch statistics. Our experiment omits running-stat updates and fixes affine scale gamma = 1 and shift beta = 0. PyTorch reference.

With learned affine parameters, the simple zero-sum and radius statements apply before that affine transformation. They are not universal properties of every layer output.

Why this matters for a real model

A batch-dependent operation means splitting a batch can change the forward computation, even when you later accumulate gradients correctly. Gradient accumulation alone does not recreate a larger batch's normalization statistics. This differs from the sample-weighting issue in our microbatch weighting experiment.

When debugging a train/eval mismatch, inspect the module mode, tracked statistics, batch construction and affine parameters before blaming floating-point noise. This toy does not measure accuracy, convergence, distributed synchronization, or the quality of running estimates. It isolates one forward-pass dependency.

The original method is described by Ioffe and Szegedy in Batch Normalization (2015). This page's plane-and-radius derivation is an explanatory analysis of the normalization equation, not evidence for a particular account of why training improves.
