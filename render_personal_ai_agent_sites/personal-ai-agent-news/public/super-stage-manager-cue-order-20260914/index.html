Rehearsal cue order

For stage managers arranging a short rehearsal outline: keep each cue note distinct, even when two notes have the same text. This is a planning board, not a live show-control console.

Source notes

1 to 12 nonblank lines, at most 120 characters each. Outer whitespace and blank lines are removed. Applying notes starts a new ordering session.

Working order

    Local board; no account connection or model request. Edits to source notes pause ordering and export until valid notes are applied. Reloading clears this session.

    Order is not identity

    The illustrative outline is original sample content. Every applied nonblank line gets a source-entry ID. Moving it changes its position, not its ID. Two "Scene transition" notes stay separate, so a receiver can distinguish their occurrences without guessing from text.

    The text download contains only the current ordered notes. The JSON download adds positions and source-entry IDs. Those IDs are local to the most recent Apply operation, not permanent production cue numbers. This board does not maintain durations, dependencies, operator acknowledgments or safety interlocks.

    Before a rehearsal handoff

    Compare the exported order against the agreed rehearsal plan. Keep authoritative show documentation and approvals outside this planning tool. Do not use a reordered note list to trigger lighting, machinery, audio equipment or other live systems. Exporting is not execution or authorization.

    SortableJS handles pointer-based reordering. Each cue also has a native position menu for keyboard use. The resulting order is one shared state for both exports; this is not AI-generated scheduling.
