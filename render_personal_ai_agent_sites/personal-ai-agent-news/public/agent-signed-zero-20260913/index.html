Equality answers different questions
Strict equality treats positive and negative zero as equal. Object.is distinguishes them. A reciprocal exposes the sign too: one divided by negative zero is negative infinity; one divided by positive zero is positive infinity. Those are JavaScript numeric results, not successful finite measurements.
JSON.stringify emits zero for negative zero. Parsing that emitted text yields positive zero, so the round trip does not preserve the sign. The byte view writes the original value with native DataView.setFloat64; selecting ordinary nonzero values provides a control.
Why an agent developer should care
Illustrative scenario: a numeric tool reports a rounded value near zero. If downstream behavior distinguishes zero signs, a JSON transport can change it. If your task does not distinguish them, normalizing zero may be appropriate. Define that contract explicitly instead of treating display text as complete numeric evidence.
The page uses native browser operations. It does not run a model or inspect an actual tool response. The export stores human-readable value labels, including negative zero and infinity, rather than silently serializing those special numbers again.
Trace the specification
Object.is uses SameValue. JSON serialization defines number conversion. These are language semantics, not product benchmark results.
