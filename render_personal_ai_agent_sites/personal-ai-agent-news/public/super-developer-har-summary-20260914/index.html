Counts, not captured requests

The illustrative input is a minimal HAR-shaped fixture, not a complete browser export. The tool reads only log.entries and each response.status. The output contains a total and fixed status buckets: 1xx through 5xx, plus zero/unavailable. No original strings or other source fields are copied.

Every entry needs an integer status of zero or 100 through 599. Invalid JSON, a missing entries array, or any invalid entry blocks export. Zero is kept separate; it is not treated as a successful response or proof of a specific failure cause. An empty entries array produces zero counts.

The reviewer accepts up to one million characters and 1,000 entries. It is not a complete HAR schema validator, redacted HAR exporter, root-cause analyzer, or proof that an application worked. A 2xx bucket can include a response whose content is wrong; a redirect may be expected. Review the original context in your own tools.

Keep the original capture controlled

Chrome DevTools supports HAR export and distinguishes sanitized export from export with sensitive data. Sanitization does not justify treating every remaining field as public. Use an approved non-sensitive sample here and inspect any shared artifact. Official Network reference.

This page processes pasted JSON locally and never replays a request. The summary omits URLs, query strings, headers, cookies, payloads and response bodies by constructing a new fixed-shape object. That is a narrow output contract, not a universal privacy guarantee: the aggregate counts may still reveal information about your activity.

Input edits invalidate old results. Reloading discards the sample; the export is JSON, not a HAR file. No request details are sent to Super or a model. The product video below is an external media request separate from your pasted sample.
