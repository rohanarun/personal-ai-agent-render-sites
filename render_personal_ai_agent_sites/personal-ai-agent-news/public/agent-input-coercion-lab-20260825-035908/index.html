Validate honestly

A rejection is useful when it explains what failed and gives the caller a bounded repair path.

Preserve the raw value

Keep the malformed input visible so debugging and recovery do not depend on a hidden conversion.

Coerce only by contract

Normalization is safe when the schema explicitly defines it and the original form cannot change the decision.

Gate costly actions

For high-impact tools, reject ambiguity before the side effect instead of treating “close enough” as valid.

This simulation is a teaching model, not a production validator. It demonstrates a contract-first pattern: validate against the schema, preserve defects, and gate consequential actions.
