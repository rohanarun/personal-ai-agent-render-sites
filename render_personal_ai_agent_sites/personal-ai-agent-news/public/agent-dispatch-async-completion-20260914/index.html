Dispatched is
not completed.

An async listener starts now and resumes later. An event-dispatch boolean tells you about cancellation, not whether the listener's task finished.

Idle

    One event, two completion boundaries

    const gate = new Promise((resolve, reject) => {
  resolveWork = resolve;
  rejectWork = reject;
});
target.addEventListener('task', async () => {
  log('listener started');
  try {
    await gate;
    log('work completed');
  } catch (error) {
    log('work failed');
  }
});
const result = target.dispatchEvent(new Event('task'));
log(`dispatch returned ${result}`);
// Later: resolveWork() or rejectWork(new Error('demo'))

    The listener reaches await and returns a promise. Event dispatch does not join that promise. The manual gate makes the gap observable without relying on a timer: the caller has already returned while the work remains pending.

    This noncancelable event returns true even when the gated work later fails. The listener catches the rejection explicitly; this demo does not generate an unhandled rejection. A real action needs its own completion contract and error path, such as a directly awaited operation or an explicit result message.

    What this proves

    The trace is produced by native EventTarget, Promise and async/await in your browser. Resolve and reject are illustrative outcomes, not network calls or agent execution. Reset releases the old gate and invalidates its UI updates; it is not a general cancellation mechanism for external work.
