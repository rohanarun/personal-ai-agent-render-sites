Ask two different questions
Did freezing succeed? A nonempty typed array rejects freezing. The attempt can still leave the object non-extensible: an exception is not a rollback. A zero-length typed-array view and a DataView can be frozen.
Can the memory still change? The separate alias addresses the same buffer in every mode. A frozen DataView can still write through setUint8. The empty view exposes no elements to write, but its buffer is not empty here. Neither successful freeze nor read-only buffer accessors establish immutable storage.
Why an agent pipeline cares
Imagine a parser hands bytes to a later verification step. A claim that the view is frozen is insufficient evidence that the later step receives the original bytes. In this lab, first attempt freeze, then write a different value and compare the trace with the visible buffer.
A defensive copy separates this particular alias, but that copy can still be changed by code with access to it. Choose an ownership contract, retain evidence of what was actually consumed, and test writes through every exposed path. This example covers ordinary, fixed-size ArrayBuffer storage only; it is not a sandbox, concurrency test or general security guarantee.
At most 20 operations per run. Reset starts over. The empty view's direct write path is intentionally unavailable because it has no indexed elements. Error messages vary by engine; the trace records the error name.
