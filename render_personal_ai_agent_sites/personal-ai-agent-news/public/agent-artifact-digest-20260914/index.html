Bytes are the contract
The trailing-space example adds one byte. The JSON example reorders keys while retaining the same key-value associations. This lab does not parse, normalize, trim or canonicalize either text before UTF-8 encoding. The digest therefore describes that encoded representation, not your interpretation of the document.
For an agent that verifies a downloaded artifact against a saved receipt, keep the algorithm and byte representation consistent. Hashing a reformatted copy is a different check. This text lab cannot verify an original file's byte-order mark or line endings: browser text input and TextEncoder determine the bytes shown here. The export contains both input strings, byte counts and digests so the experiment can be repeated.
What the color map does not prove
Each square compares one of 256 output bits. The changed-bit count is an observation for this pair, not a similarity score or a quality metric. There is no promise that every small edit changes exactly half the digest bits.
Different digests imply different hashed input bytes. Equal digests are not mathematical proof that arbitrary inputs are identical; this lab also compares the bytes directly. A digest alone does not identify an author, authorize an action or prove that a file is safe. A trustworthy reference is a separate requirement.
Native hashing, explicit limits
The browser's SubtleCrypto.digest implements SHA-256 here. It operates on the complete encoded input in memory. This page limits each text to 50,000 characters and requires Web Crypto in a supported secure context. No model or remote hashing service is called.
