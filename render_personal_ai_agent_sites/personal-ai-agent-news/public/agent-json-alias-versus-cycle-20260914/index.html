Repeated is different from circular
Without the parent edge, native serialization writes both properties, even when a and b reference the same object. JSON text carries their values, not their shared object identity. Parsing that successful text produces separate a and b objects.
Adding a.parent = root creates a path back to an ancestor. With these ordinary enumerable properties and no replacer or toJSON method, JSON.stringify throws a TypeError. The exact message can vary by browser; the error shown above comes from your browser.
Why a global seen-set can lose data
A replacer that removes every object seen before can remove b in the shared, non-circular example. Repeated identity is not enough to prove an ancestor cycle. Replacing a cycle with text also changes the payload's meaning; it is not transparent repair.


Before an agent writes its event log
Illustrative scenario: an agent attaches the same task object to two event fields. That graph can serialize successfully, but the receiving program will not recover aliasing merely by parsing the JSON. Adding a parent pointer for debugging changes the situation and can make logging fail.
Choose a deliberate payload contract: bounded scalar fields, explicit IDs and references, or a documented graph format understood by both sides. Do not silently omit an event branch just to make serialization succeed. This experiment exports a small, acyclic observation with flags and strings, not a generic cycle-removal utility.
A JSON failure is about this encoding boundary, not evidence that the graph is invalid for every purpose. Structured cloning has a different reference contract. No network request, model call or production event is sent here.
