Abort Listener Lifetime

A cancelled agent run should stop receiving new progress events. Does removing its listener also stop the event source? These are different lifetimes.

    One signal, one run

    The run listener uses an AbortController signal. An independent observer has no signal. The late listener uses the same run signal, even if it has already been aborted. Every dispatch is a real browser EventTarget event, not a simulated scheduler.

    target.addEventListener('progress', onRun, {
  signal: controller.signal
});
target.addEventListener('progress', onObserver);
controller.abort();
target.dispatchEvent(new Event('progress'));

    After abort, the run listener is removed. A new listener registered with that already-aborted signal is not added. The independent observer still receives events: cancelling a subscription does not cancel the producer.

    Where this matters

    An agent dashboard can tie several subscriptions to one run controller and release them together. This experiment covers future synchronous event delivery only. It does not undo completed callbacks, interrupt arbitrary JavaScript, or cancel a remote task. Work already started inside a callback needs its own cancellation support.

    The late-listener button is a single registration attempt per experiment. Reset creates a new target and controller. The trace is capped at 30 actions so every export remains bounded.
