Unequal batches, unequal votes

Six sample gradients. Two microbatches. Moving the split should not change their overall average, but an unweighted average of batch means does exactly that.

The denominator is part of the objective
Let g_i be each sample's gradient at the same parameter vector. This experiment uses six equally weighted, independent loss contributions. For a mean loss L = (1/6) sum_i l_i, linearity gives grad L = (1/6) sum_i g_i.
a = sum(A) / k
b = sum(B) / (6-k)
correct = (k/6)a + ((6-k)/6)b
naive = (a+b)/2
The connecting line joins the two batch means. The naive result is always its midpoint. The correct result is nearer the mean of the larger batch. When k = 3, both formulas agree. When the batch means happen to be equal, they agree for any split.
naive - correct = (1/2 - k/6)(a-b)
This identity separates the two causes of error: unequal counts and different batch means. Changing the split recolors the points but leaves the green result fixed. Changing the last sample really changes the data, so the green result moves too.


Try the counterexample
  1. At the default split, A contains only (2,0,0). B contains the other five samples. The correct average is (1/6,1/6,0), while the mean of means is (0.9,0.1,0).
  2. Choose Equal split. The two results coincide; the cube and sphere overlap. This is agreement, not a missing marker.
  3. Move the split back to one sample. That sample receives weight 1/2 in the naive result, while each B sample receives 1/10. The intended weight was 1/6 for every sample.
  4. Vary the last gradient. Compare how the actual mean and the weighting error change. The displayed Euclidean gap measures vector error, not training loss.
The endpoints are three gradient coordinates, not data embeddings or model parameters. A descent step would use the negative gradient. The faint coordinate axes supply orientation; orbiting changes the view, not the calculation.


Carry the right counts into training
For this sample-mean objective, accumulate summed sample gradients and divide once by the total sample count, or weight each batch mean by its share of that count. In token-level language-model training, the relevant count may instead be valid, non-padding tokens. Accelerate's official guide explicitly discusses this variable-size case and provides framework-specific scaling code.
Do not paste a second divisor into a framework that already scales your losses. Distributed averaging, class weights, ignored labels and mixed precision can change the bookkeeping. Match the actual loss reduction and test the accumulated gradient against one reference computation.
This toy keeps all gradients fixed at one parameter state. Optimizer steps between microbatches, batch-dependent layers, changing randomness and nonlinear operations such as clipping may prevent equivalence even after the denominator is correct. It is not a simulation of those effects.

The authored vectors are (2,0,0), (0,2,0), (0,0,2), (-1,0,0), (0,-1,0), (0,0,-s), in that order. Batch A takes the first k. Vector operations and rendering use bundled Three.js; no model API or training job runs. The export includes all six vectors, both means and the error.
