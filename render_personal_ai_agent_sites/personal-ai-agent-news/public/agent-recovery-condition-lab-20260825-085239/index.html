Recover with a condition.

A failed action is not a plan. An agent needs a recovery condition that says what must become true before it retries, repairs, or asks for help.

Recovery is a bounded transition from failure to a known-good state, not a loop with a nicer name.

Recovery Condition Lab

Set how clear the failure signal is, how reversible the action was, how costly a retry is, and how severe the consequence of repeating it would be.

70/100 recovery readiness
Repair, then retry once.

The failure is legible and the action is reversible enough for one bounded recovery attempt.

Every retry needs a changed condition, not just a changed mood.

Name the change

A retry is meaningful only when it changes an input, precondition, route, or permission that could explain the failure.

Limit the loop

Set a retry budget and a stopping condition before the first attempt. Repetition without new evidence is not recovery.

Preserve the trace

Record the failure, repair, and new postcondition so evaluation can distinguish recovery from accidental success.
