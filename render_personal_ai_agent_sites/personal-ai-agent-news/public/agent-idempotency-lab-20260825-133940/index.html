The effect gate

Make the retry answer a precise question.

An agent often sees timeouts, reconnects, and duplicate deliveries. The policy boundary is simple: identify the operation, look for its recorded result, and only create a new effect when the key is genuinely new.

A useful mental model

Durability turns a retry into a lookup.

Without a durable operation identity, an agent cannot tell whether a timeout means “nothing happened” or “the effect happened but the reply was lost.” Idempotency makes that uncertainty explicit and bounded.

Identify

Give the logical operation a stable key that survives transport retries.

Record

Persist the result beside the effect, so a later attempt can replay it.

Hold when unclear

If identity, durability, or result ownership is uncertain, waiting is safer than guessing. A bounded hold protects users from duplicate charges, duplicate messages, and repeated tool mutations.
