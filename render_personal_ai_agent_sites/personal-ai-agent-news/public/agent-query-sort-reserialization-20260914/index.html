Query sorting changes URL text

An agent can preserve every decoded value and still rewrite a request URL. Compare a read with a native, in-place sort before assuming that a cleanup is harmless.

Before sorting

    Current URL
      The baseline is the browser-parsed URL, not necessarily your original spelling. Loading only reads searchParams; sorting mutates the same URL object. Nothing is fetched. Do not enter private URLs or credentials.
      

      Two changes, one method
      url.searchParams.sort() orders decoded keys by UTF-16 code units. It is stable: equal keys keep their original relative order. It does not sort the values within a repeated key and returns undefined, not a new query object.
      Updating the attached searchParams also serializes the query using form-style encoding. In the example, a space changes from %20 to + and a tilde becomes %7E. Even an already sorted query can change spelling.
      Already sorted does not mean unchanged
      Load https://example.test/run?a=two%20words~. Reading the pairs leaves the baseline alone. Sorting leaves the same pair in place but rewrites its encoding. Sorting again is unchanged for this example.
      Stable keys are not sorted values
      Load https://example.test/run?b=1&a=z&a=a&A=0. Uppercase A sorts before lowercase a. The two lowercase a values remain z then a. This is code-unit ordering, not locale-aware alphabetical ordering.
      

      At an agent's request boundary
      Illustrative scenario: an agent receives a prebuilt download URL and sorts its query to tidy a log. If it then sends the mutated URL, it is no longer sending exactly the supplied text. A destination that signs exact query text or treats parameter order as meaningful may reject that change. The destination's documented canonicalization rules decide this; this experiment neither signs nor verifies a request.
      Keep display transformations separate from the original request. When a service requires canonicalization, implement that specific contract rather than treating a generic key sort as equivalent. Equal decoded pairs do not prove equal server behavior, permissions, cache identity or signatures.
      The exported observation includes the entered text, parsed baseline, current URL and decoded ordered pairs. It is a browser experiment, not a network trace or production validation.
