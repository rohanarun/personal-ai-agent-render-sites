Two Layers of Defaults

A default configuration object is not the same thing as a default property. Send a value across each boundary and observe the actual JavaScript call.

Observed sequence
    The first boundary: the argument
    With an outer default, an omitted argument or explicit undefined invokes outerDefault(). That function returns an empty object. Passing null does not invoke the default; destructuring it throws before the function body begins. Without an outer default, an omitted argument and explicit undefined also fail.
    The second boundary: the property
    Once an object is available, the property initializer runs only when the extracted retries value is undefined. Missing properties in these plain objects therefore use it too. Null, zero and false survive unchanged. The initializer is a function here so its evaluation becomes visible in the sequence. Returning a value successfully does not establish that it is a valid retry count.
    What an agent adapter should decide
    Imagine a tool adapter receiving a retry configuration from a caller. Its contract needs to distinguish an absent setting, an explicit zero, and malformed input. A convenient default is not a schema validator. Treating every falsy value as missing can silently replace a deliberate zero; accepting null without a policy can push an invalid value deeper into execution.
    This experiment calls local functions, not a model or a remote tool. The result is a language observation, not a recommendation that every adapter should use three retries. Decide the accepted types and range for your own tool, validate at the boundary, and test omitted, undefined, null and zero separately. JSON has no undefined value, so direct JavaScript callers can exercise cases a JSON transport cannot represent.
