Retry with guardrails

Keep the retry budget, add backoff, and make replay semantics explicit before the tool can mutate state.

Backoff protects neighbors

When every failed worker retries at once, a temporary outage becomes a synchronized surge. Delay and jitter spread demand across time instead of hiding the overload.

Idempotency protects meaning

Retries are only safe when replaying the same request cannot create a second charge, message, or reservation. Recovery needs a durable identity for the intended side effect.
