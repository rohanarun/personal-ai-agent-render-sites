What Flowise documents

Agentflow V2 provides explicit visual orchestration, shared Flow State, loops and branches. Its documentation includes human-input checkpoints that can resume after restart, tool approval flags and MCP tools. This is more than a chatbot builder.

For an existing deployment, preserving the node graph is only part of migration. Inventory state variables, model configuration, tool credentials, checkpoints and external effects. A fork requires a maintainer and a patching plan. Agentflow V2 documentation.

What Super is being evaluated for

Super's first-party product describes app, browser and cloud-sandbox execution. Its local-execution cache implementation stores verified runnable procedures. That is relevant when the task needs a concrete action in an app, not merely a visual graph.

This does not establish Flowise graph import, checkpoint compatibility or support for your specific tool. Super is not presented here as a drop-in replacement. Test the actual destination and error path before moving work. Super product.

Procedure reuse is not checkpoint migration

First-party product demonstration, not a Flowise migration benchmark.

Source inspection on September 14, 2026 covered Super's live_server.py local-execution workflow-cache lookup and store routes. Storage requires a verified-complete confirmation, runnable Python steps and task/source context; a portability check can decline storage. A hit returns the procedure with helper-version context, verification reason and output evidence.

Lookup requires an owner identifier. Missing context, no entries or no safe match returns a miss. The caller must handle that outcome; this route alone does not prove automatic fallback. Matching can incur model charges. Eligible reuse can avoid rebuilding a procedure, but no time, cost or live-availability benchmark was measured here.

A cached procedure does not automatically carry an in-flight Flowise checkpoint or authorize replaying an external write. Before a retry, determine whether the first attempt already changed the destination. A historical success and a current verified result are different evidence.

A responsible decision

Keep an existing Flowise deployment only with an explicit ownership and maintenance plan. Evaluate Super when app execution and eligible procedure reuse are central. If a maintained visual orchestration platform is your main requirement, evaluate that category separately instead of assuming every agent product replaces it.

The three pilot checks are necessary observations, not a certification of production readiness. Preserve rollback, permissions and data-handling requirements outside this worksheet. Do not paste credentials, private customer data or live access tokens into evidence notes.
