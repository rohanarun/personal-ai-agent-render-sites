Define the wire type

BigInt and JSON need an explicit conversion policy: ordinary JSON.stringify throws for a BigInt value. This fixture does not patch built-in prototypes or install a generic replacer.

The left path attempts to serialize {count: value}. The right sends {schema: "count-decimal-v1", count: value.toString()}. Its receiver checks the schema and decimal-string field, then converts only that field back to BigInt. The output shows the parsed field's string type before restoration and the restored bigint type afterward.

Do not guess from digits

An arbitrary digit string might be an identifier or text, not an integer. A known field contract avoids converting every numeric-looking string in a payload. This lab accepts canonical decimal notation: no whitespace, plus sign, leading zeros or negative zero. The 100-digit limit bounds this fixture, not the BigInt type.

The receiver shown here expects exactly two own fields and the declared version. It is a demonstration of a narrow schema, not a universal validator. Real callers still need size limits, domain constraints and error handling at their own transport boundary.

Agent result handoff

An illustrative tool may return a large exact counter. Define its wire representation before handing it to a consumer that expects JSON. A successful stringify is not enough: check the receiving type and value too. The equality observation here compares BigInt values, never rounded Number conversions.
