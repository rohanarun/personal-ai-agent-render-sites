Transparent sprite trim

For game artists preparing a single sprite: remove fully transparent outer borders, keep every decoded pixel with alpha above zero, and add a deliberate transparent margin.

Original

Trimmed + padding

Local processing; no image upload or model request. Up to 8 MiB, 4,096 pixels per side and 16 million pixels. Animated PNG is rejected. Checkerboards are preview backgrounds, not exported pixels.


Keep the faint edge
This tool finds the bounding rectangle of pixels whose decoded alpha is greater than zero. It does not apply a visibility threshold. A nearly invisible pixel can therefore keep a large border. The original example is a geometric sprite drawn here, not a commercial game asset. Its optional alpha-1 pixel makes that boundary visible in the dimensions.
Padding is new transparent space around the detected rectangle; it can extend beyond the original image. A completely transparent image has no content rectangle and cannot be exported here. An opaque background is content, so this is not background removal.
Position and animation handoff
Trimming changes the image origin and dimensions. The manifest records source dimensions, crop origin and output padding. A source point (x, y) maps to (x - crop.x + padding, y - crop.y + padding). Update your engine's pivot and placement explicitly. Trimming animation frames independently can cause apparent jitter; this single-image tool does not compute shared frame bounds or an atlas.
The PNG is re-encoded from browser-decoded canvas pixels. Original file metadata, indexed palettes, profiles and byte identity are not preserved. No lossless color-management or hidden RGB guarantee is made. Keep the original source file.
