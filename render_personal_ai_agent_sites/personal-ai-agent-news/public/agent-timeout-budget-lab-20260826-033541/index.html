Why stopping matters

A timeout is not only a network setting. It is a control boundary that lets an agent choose a fallback, expose partial progress, or ask for help instead of silently consuming the entire run.

Bound the wait before you add retries.

Retries can improve completion when failures are transient, but they also multiply the time and side effects a workflow may spend on one operation.

Set a total deadline first. Then allocate time across attempts, backoff, and downstream work so the agent can still produce a legible result when the ideal path is unavailable.
