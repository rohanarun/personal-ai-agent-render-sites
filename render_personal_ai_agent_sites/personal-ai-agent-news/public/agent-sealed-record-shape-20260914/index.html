Two different boundaries
Object.preventExtensions stops adding own properties but does not automatically make existing ones non-configurable. Object.seal also makes existing own properties non-configurable. Existing writable data properties remain writable.
The lab uses Reflect.set and Reflect.deleteProperty, whose boolean return values expose these ordinary-object failures without relying on strict-mode assignment exceptions. Repeating a deletion of an already absent property returns true, which is not evidence that anything was removed on that call.
Why an agent controller should care
An illustrative job record starts as { status: "queued" }. A sealed shape can catch accidental field additions through the returned failure result; it does not validate allowed status strings, authorize an actor, persist state, or make the record immutable. Ignoring a false result can still hide a failed update.
This is native JavaScript, not an LLM or a live task runner. Each policy change starts a fresh record. The trace includes each requested operation, its boolean result, and a snapshot of own fields and descriptors. Exports are limited to 30 operations per run.
