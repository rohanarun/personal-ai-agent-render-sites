    Try the retry
    Add "fetch" again: its position stays the same. Delete it, then add it: it moves behind "parse" and "verify". Deleting a missing ID does not alter the set. Take first reads the first iterator value and then deletes that value; this is our queue operation, not a built-in Set method.
    Membership is not a job ledger
    A Set keeps unique values in insertion order. It does not remember a deleted item's old position when that item is added again. This example only tracks waiting IDs, not attempts, owners, success, or side effects.
    Illustrative engineering decision: if a retry belongs at the front, make that scheduling policy explicit. A deduplicated collection alone is not durable storage or exactly-once execution. Export a trace that demonstrates the intended order before adopting a queue representation.

    Separate identity from scheduling
    These task labels are exact strings. Two labels that describe the same work can still be distinct IDs. Conversely, one reused label can collapse two different requests. Decide identity before using deduplication as a queue policy.
