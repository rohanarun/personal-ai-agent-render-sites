Observe membership, not just the value

WeakMap keys can be objects or non-registered symbols. This fixture uses objects. The original and alias are the same object; the lookalike is a different object. Storing undefined still creates an entry: has returns true, although get returns undefined for both that entry and the absent lookalike.

Deleting through the original also removes the alias's entry because they share a key. WeakMap provides no keys iterator or size property. The chart queries three known references; it is not enumerating the map.

WeakMap does not keep its keys alive by itself. This lab deliberately retains all three references and neither requests nor measures garbage collection. Deleting an entry is an explicit operation, not evidence of collection. See the WeakMap reference.

A useful temporary attachment

Imagine an agent's in-memory task object needs a rendering hint for a debug panel. That annotation may belong to the particular object instance. The illustrative "ready" string in this lab is such an annotation, not proof that any external task is ready.

A restart, a reconstructed object or a different process needs a separate persistence contract. For a durable task ledger, decide what identifier survives those boundaries, what completion evidence is saved, and how a reader detects outdated records. Merely swapping collection classes does not answer those questions.

Read the export carefully

The download contains observations for named references and a chronological list of this run's store/delete actions. Undefined is encoded explicitly as a type label instead of silently disappearing in JSON. It is not a backup of the WeakMap, a live task inventory or a memory-leak measurement.

Changing the selected value starts a fresh fixture. Reset discards the local fixture and its observation history. Store can be repeated; deleting an already absent entry returns false. No external action, model request or worker is launched. Published September 14, 2026 by Super Powers AI.
