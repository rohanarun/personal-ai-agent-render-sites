Uniform mixing, including the correct class
With three classes and label A, this convention mixes the one-hot target with a uniform distribution:
q = (1 - epsilon) (1, 0, 0) + epsilon (1/3, 1/3, 1/3)
At epsilon = 0.3, the target is (0.8, 0.1, 0.1), not (0.7, 0.15, 0.15). The latter distributes the smoothing mass only among incorrect classes and uses a different convention. The PyTorch documentation specifies mixing with a uniform distribution.
The gradient changes sign
For p = softmax(z), cross-entropy is L = -sum(q_i log p_i). Because q sums to one, its logit derivative is dL/dz_i = p_i - q_i.
In the Confident A example, logits (4, 0, 0) put about 0.965 probability on A. With smoothing 0.3, q_A = 0.8, so A's derivative is about +0.165. A descent step lowers that logit. With the Hard label example, q_A = 1 and the derivative is about -0.035, pushing it upward instead.
Changing epsilon changes the loss target, not the prediction for fixed logits. The green point therefore stays put while the rose point moves toward the center. This is training regularization, not a post-processing rule that mixes every prediction with uniform probabilities.


A finite optimum replaces an infinite margin
For a freely chosen probability vector, cross-entropy is minimized at p = q. At epsilon = 0.3, logits (log 8, 0, 0) produce exactly (0.8, 0.1, 0.1). The minimum loss is the target entropy, about 0.639 nats, not zero. A shared neural network need not be able to fit every example's target independently.
Check the logit gap
Equal B and C logits give p_A / p_B = exp(z_A - z_B). Matching the smoothed target requires z_A - z_B = log((1 - 2 epsilon/3) / (epsilon/3)). This is finite for 0 < epsilon <= 1. At zero smoothing, the target is a corner: finite softmax logits cannot make the other probabilities exactly zero. At epsilon = 1, the target is uniform and carries no information about which class was labeled.
What this does not establish
No dataset is trained here. We do not measure accuracy, calibration, robustness or the best smoothing amount. "Confident" describes the displayed prediction relative to this target, not whether its confidence matches real-world correctness. Too much smoothing can discard useful label information; evaluation must match the actual task.
