    Replay state, not side effects

    This replay only applies recorded results to local state. It never calls an inventory service. A request records intent; its result records the reported outcome. An absent result leaves the outcome unknown. Duplicate result IDs are ignored to prevent applying the same change twice.

    Starting state and event rules

    Initial stock: 10. Version 1 events belong to the same synthetic run. A request opens a pending call. A successful result closes that call and applies its stock delta. Results must match a pending call. The duplicate fixture repeats an identical event ID and payload. Conflicting payloads under one ID would require an integrity error in a production system.

    This small projection illustrates recorded state reconstruction. It does not reproduce model reasoning, verify that a real external action happened, or implement a distributed event store.
