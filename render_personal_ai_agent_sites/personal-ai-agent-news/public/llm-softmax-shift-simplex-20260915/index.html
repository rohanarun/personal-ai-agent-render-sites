Different logits.
The same probabilities.

Softmax only sees relative logits. Add a common offset and the probability point stays put. Change temperature and it moves.

Base logit 3 is fixed at zero. Actual logits are [base 1 + offset, base 2 + offset, offset].



Try three predictions
  1. Start at [2, 1, 0], temperature 1. The first class is most likely, but the point is not at its vertex: probabilities are approximately [0.6652, 0.2447, 0.0900].
  2. Add 1000 to all three logits. You now have [1002, 1001, 1000]. The relative gaps have not changed. A naive exponential overflows in JavaScript here; the stable softmax result remains finite.
  3. Increase temperature to 4. The point moves toward the equal-probability center. Make all base logits equal: every positive temperature now gives [1/3, 1/3, 1/3].
The gold curve holds base logits fixed and varies temperature; the reference ring uses the current temperature but zero common offset. Their roles are different. Orbit the scene to inspect its planar geometry, or return to the face-on view.


One direction disappears
For positive temperature T, define pᵢ = exp(zᵢ/T) / Σⱼ exp(zⱼ/T). Adding c to every logit multiplies every exponential by the same factor exp(c/T). That factor cancels between numerator and denominator:
softmax((z + c·1)/T) = softmax(z/T)
log(pᵢ/pⱼ) = (zᵢ − zⱼ)/T
There are three logits but only two independent probability coordinates because their sum is one. Entire lines parallel to [1,1,1] in logit space map to one probability point. The display plots that resulting point in probability space; it does not claim that logits themselves are bounded by this triangle.
Temperature scales the gaps, so it generally changes probabilities even though it preserves the ordering for T > 0. As T becomes large, the distribution tends toward uniform. As T approaches zero from above, mass concentrates on the largest logits; tied maxima share the limiting mass.


Stable computation uses the same invariance
Subtracting the largest scaled logit before exponentiating makes every exponential at most one. The normalization is unchanged mathematically. SciPy's softmax documentation explains this shift and links the numerical-analysis paper behind it.
u = z/T
pᵢ = exp(uᵢ − max(u)) / Σⱼ exp(uⱼ − max(u))
This page computes probabilities with TensorFlow.js softmax on its CPU backend, entirely in the browser. The diagnostic reports the largest difference from the zero-offset result. The exact identity need not be bit-for-bit exact in float32: scaling and rounding can alter tiny gaps. Very large offsets can destroy information before softmax even runs. The slider's bounded range is an experiment, not a guarantee for arbitrary inputs.


What this says about language models
A larger absolute logit does not by itself mean greater confidence across two different logit vectors. Relative differences and temperature determine this normalization. Adding a common bias cannot favor a token; changing one token's logit can.
Real language models have far more than three candidate tokens. Top-k filtering, nucleus sampling, masks and penalties are additional operations not simulated here. These probabilities are not a claim about factual correctness, calibration or any trained model. No model inference or generation API is called.
The lesson is narrow but useful: separate a transformation that changes the distribution from a transformation that merely changes its representation.
