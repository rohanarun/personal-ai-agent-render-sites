The Latin-1 trap

Try the accented example. Direct btoa accepts its characters because their values fit within one byte. But its bytes differ from UTF-8, so the two Base64 strings differ. A receiver expecting UTF-8 cannot treat the direct result as the same encoded text.

Try the beyond-one-byte example. Direct btoa rejects characters outside its byte-string range with InvalidCharacterError. The other path first uses TextEncoder to create UTF-8 bytes, encodes those bytes, and decodes them back through TextDecoder.

Define the wire contract

Illustrative agent scenario: one tool encodes a text result while another decodes it. Agree on the text encoding, the Base64 variant, and whether the payload is text or binary. This page uses standard Base64, not Base64url, and does not read files or call a model.

Base64 is reversible representation, not encryption, authentication, or validation. Do not use it to conceal credentials. For binary files, encode the original bytes rather than decoding them as text first.

The UTF-8 path reports exact equality with the input. TextEncoder converts isolated surrogate code units to replacement characters; such malformed JavaScript strings need not round-trip exactly. The decoder here preserves a leading byte-order-mark character by using ignoreBOM: true.
