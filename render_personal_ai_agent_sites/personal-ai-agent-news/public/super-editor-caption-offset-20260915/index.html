Caption Offset Desk

How to shift a subtitle draft without editing every cue timestamp.

Local, simplified WebVTT export. No transcript generation, upload or model request. The product video makes an external media request.

Positive moves cues later; negative moves them earlier. Offset range: -600,000 to 600,000 ms. Source limit: 20,000 characters and 100 parsed cues. Cue endpoints must remain between zero and 99:59:59.999.

Parsed cue review

    This is not a lossless subtitle editor

    The browser's native text-track parser may omit malformed cues. A loaded track is not proof that every source cue survived. Review the list against your original before exporting. Changes to the source clear the parsed result; changes to the offset clear your review confirmation.

    Output contains millisecond timestamps and plain cue text. Cue IDs, positioning, styles, regions, voice tags and inline timing are not preserved. Formatting markup is flattened, literal text is escaped, and consecutive blank text lines are collapsed. Do not use this workflow when those features matter.

    All cues receive the same offset. Durations and relative gaps stay the same; this does not correct drift, overlapping captions, transcription errors or reading speed. A negative result is rejected, never clamped or silently dropped. Recheck the downloaded file with the actual media in your editor.

    What the computer-use cache reuses

    The first-party response proxy can reuse successful responses for exact repeated requests. Misses go upstream; a hit avoids another upstream model call but not necessarily execution or infrastructure costs.

    Separately, the inspected workflow-cache code returns a verified workflow and evidence on a safe match. Missing context or no safe match returns a miss for the caller to handle, and matching may incur usage. The mechanisms are distinct. Neither processes these captions.
