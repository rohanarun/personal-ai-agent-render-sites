Presence is not enumerability

The constructor creates a non-enumerable message property. For an ordinary object without a custom serialization override, JSON.stringify visits enumerable own string-keyed properties. The inherited name and non-enumerable message are therefore absent from the raw output here.

Assigning a code adds an enumerable own field. Raw JSON can then contain the code while still losing the message. The explicit report reads chosen fields and writes them into a new plain object. An empty message remains an empty string; it is not evidence that no error occurred.

Choose a reporting contract

A useful agent failure record needs deliberate fields and a redaction policy. This example includes name, message and an optional illustrative code. It excludes stack and cause. That exclusion is not automatic secret removal: a message can itself contain credentials or personal data. Do not paste sensitive production errors here.

This is a native JavaScript serialization experiment, not a logging SDK or universal error normalizer. Arbitrary thrown values, proxies, getters, cycles and custom toJSON methods require separate handling. No tool, model or network request is executed. Export contains the inspection, not the original Error instance.
