Inspection can execute code

A tool result can contain a getter instead of a stored value. Observe which operations invoke it.

A read is an operation
This ordinary object has an own property named result, defined with a getter. Each invocation increments a counter and returns a new illustrative string, or throws when selected. Reading object.result invokes that function. Repeated reads therefore need not be stable observations.
JSON serialization reads the enumerable result property in this fixture. Turning enumeration off omits it from JSON, but a direct read still invokes it. Descriptor inspection instead reports the accessor's configuration and the presence of a getter without calling that getter on this ordinary object.
Why a tool wrapper matters
Illustrative scenario: a wrapper computes result lazily. A diagnostic serializer reads it before the consumer does. The diagnostic step may therefore perform computation, throw an exception, or change what a later read observes. This lab only changes a local counter; it makes no network request and evaluates no supplied code.
The descriptor view is a summary: function presence is displayed as a boolean rather than serialized away. It distinguishes the definition of a property from the value returned by evaluating it. A missing value field in an accessor descriptor does not mean the getter returns undefined.
Do not turn this into a security promise
This fixture is an ordinary object, not a Proxy. Descriptor inspection of a Proxy can invoke its trap. Arbitrary objects may also provide other hooks such as toJSON. This page does not demonstrate a universal side-effect-free inspection procedure or a sandbox for untrusted values.
