Thenable or value?

Promise.resolve is not always a passive wrapper. The kind of object returned by an agent tool changes what happens next.

The same input, two resolutions
In the custom case, one object has a callable then method. This demonstration increments a counter each time that method is invoked and returns a different illustrative result. Resolving that same thenable twice calls its method twice. That behavior belongs to this thenable; not every library starts new work in then.
The native case constructs one Promise, whose executor runs once. Both Promise.resolve calls return that same native Promise here. Both observers receive its result without rerunning the executor. The plain object is instead received as a value by two distinct fulfilled promises.
Inspect the actual contract
A tool wrapper may return a promise, a thenable supplied by another library, or ordinary data. Treating them as interchangeable can hide surprising behavior. A thenable can execute code when adopted. Resolving a native promise again is not a generic retry mechanism.
The throw option applies only to the thenable. Its two invocations throw illustrative errors, which become rejected outcomes. This lab attaches rejection handlers immediately. It makes no external requests and does not evaluate user code. Each run creates fresh inputs and clears the previous trace.
The trace also records a synchronous checkpoint after both resolve calls. Thenable method invocation and outcome observers appear afterward. These are event-order observations, not latency measurements. The two green or red bars represent fulfilled or rejected outcomes; they are not timing bars.
Evidence and next step
MDN: Promise.resolve describes thenable adoption and native-promise reuse. The native identity result here assumes the unmodified Promise constructor in the same realm; it is not a claim about all subclasses or cross-realm objects.
