The illustrative example includes epoch zero, a positive timestamp and a negative timestamp. Changing units changes the instant, not the timezone. Confirm the unit against the source system's schema before attaching this output to a support ticket.

Input is parsed as an integer before conversion. Each valid value becomes a JavaScript Date and an ISO UTC string. Values outside Date's supported range are rejected, rather than rounded or silently clamped. Negative numbers represent instants before January 1, 1970. UTC output ends in Z; it is not a customer's local time.

This is a column review, not a log parser, clock-synchronization test or proof of event order. Two systems can report misleading timestamps when their clocks differ.
