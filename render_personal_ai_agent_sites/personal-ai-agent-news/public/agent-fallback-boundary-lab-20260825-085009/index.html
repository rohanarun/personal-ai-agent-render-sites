Know where to stop.

A fallback is not a second guess. It is a boundary that keeps an agent useful when its preferred path is unavailable, unsafe, or no longer trustworthy.

Graceful degradation preserves intent. It does not hide that the original capability failed.

Offer a bounded fallback.

The primary path is shaky, but a lower-capability mode can still preserve the user's intent.

Every fallback needs a visible boundary and a recovery route.

Declare the loss

Say what the fallback cannot do. Hidden capability loss becomes a trust problem when users assume the primary path still holds.

Protect the invariant

Degrade convenience before safety, authorization, or correctness. The user's core constraint should survive the fallback.

Return upward

Record the failure and define what would restore the primary path. A fallback without recovery becomes a quiet dead end.
