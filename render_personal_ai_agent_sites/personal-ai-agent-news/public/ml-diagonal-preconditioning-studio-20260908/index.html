Remove scale imbalance before iterating

Preconditioning modifies a linear system using an easily applied approximation to its matrix. Diagonal choices are inexpensive and can help when coordinate scales differ. They do not remove every source of difficult geometry.

This experiment uses a symmetric coordinate change e = P y. The error objective is F(e) = e transpose A e / 2, so in y coordinates the same value is y transpose C y / 2. A and C are positive definite throughout the controls. The scaled run maps its iterates back with P before its original objective is measured.

A fair, explicit iteration rule

Each run uses its own optimal constant step for worst-case Euclidean error contraction on its symmetric positive-definite Hessian: eta = 2 / (smallest eigenvalue + largest eigenvalue). Its update is z next = (I - eta H) z. This is fixed-step gradient descent on an error quadratic, not conjugate gradients or an adaptive optimizer.

Both start from e = [-1, -1]. The scaled initial state is y = [-s, -1]. The origin represents the error relative to a minimizer, not an assertion that every optimization problem has a zero solution.

Scaling is not a cure for coupling

For this family, C = [[1, r], [r, 1]], independent of s. Its eigenvalues are 1-r and 1+r, giving condition number (1+r)/(1-r). At r = 0 it becomes identity, and one scaled step solves the error equation. As r approaches 1, coupling remains difficult even after the diagonal imbalance is removed.

For either Hessian, the worst-case contraction factor is (condition - 1)/(condition + 1). The original matrix becomes increasingly ill-conditioned as s grows. At s = 1, the two methods are identical. These algebraic checks are specific to this displayed family; the studio is not a wall-clock benchmark or a promise of neural-network training speedups.
