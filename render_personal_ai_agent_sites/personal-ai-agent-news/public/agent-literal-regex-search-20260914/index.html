Three punctuation traps

The dot in a.b can match another character. Brackets in [id] form a character class, so the raw pattern matches an i or d rather than the whole label. C++ is not a valid JavaScript regex pattern as written. Escaping changes these inputs into literal patterns instead of interpreting them as syntax.

The amber marks are observed non-overlapping matches from a fresh global regular expression. Matching is case-sensitive. Exported indices are zero-based UTF-16 offsets, not byte positions. Fixed labels keep the raw-pattern experiment bounded; you can edit the text up to 5,000 characters.

Protect the intended operation

In an illustrative agent workflow, a filename, product label or field name may contain punctuation. If the job is literal lookup, that punctuation is data. If the job explicitly asks for a regex, it is syntax. Those are different tool contracts; the interface should say which it accepts.

RegExp.escape returns a pattern string, which may include hexadecimal escapes even for an initial letter. That representation can look unlike the original label while still matching it literally. This page uses the native implementation and reports unsupported browsers rather than substituting an improvised escaping rule.

Escaping is not authorization, input validation for every context or a guarantee that surrounding regex code is efficient. It does not make a fuzzy search, normalize Unicode, or infer whether the user meant a whole word. For simple literal containment, a string operation can be sufficient; this lab specifically examines regex construction.

Evidence and next step
