Different starting points

Retool: a connected app surface

The current new app builder creates React-based apps from natural language, with components, resources and functions. Its publishing checklist includes function approval, and published apps use authenticated access. The classic editor also remains documented for component-based interfaces, API/database queries and JavaScript logic.

Our assessment: Retool is the more directly documented starting point for this example when a team needs a shared review UI, controlled data connections and write-back. Configuration and testing still matter; the local table above demonstrates none of those production controls.

Super: an assistant workflow

Super's first-party product describes an assistant with her own apps, browsers and cloud sandboxes. The source-inspected workflow cache below provides a concrete mechanism for reusing eligible procedures. That is a different starting point from administering a team review application.

Our assessment: evaluate Super for a specific approved task across an app workflow. Do not assume this proves Retool-style roles, direct database governance or compatibility with your destination. Verify the real result in a small pilot before expanding scope.

Permissions and pricing are part of the choice

Retool's permission documentation distinguishes default groups on Free/Team, custom groups and per-environment resource access on Business, and additional object-role/admin granularity on Enterprise. Hiding a column in our local table is not any of those controls.

The Retool pricing page lists Free for up to five users, 500 workflow runs/month and 250 AI credits/month. Paid pricing distinguishes builders and internal users; agents have separate billing. The retrieved page was localized to GBP and offered billing/deployment selectors, so obtain the applicable quote rather than treating an unlabeled rate as universal.

Super's published pricing lists a pay-as-you-go wallet, with managed device tiers of $199/month for 10 devices and $999/month for 100 devices. These are not per-seat equivalents to Retool. We do not infer lower total cost; confirm included usage, deployment, governance and support for your workload.

There is implementation behind workflow reuse

First-party computer-use cache demonstration; not a Retool comparison test.

On September 14 we inspected the publisher's workflow-cache lookup and verified-store routes. Saving requires an owner, a verified-complete flag, task/source context and runnable Python workflow steps. A portability check may decline storage. A hit returns a reusable workflow with helper-version information, verification reason and output evidence. This is procedure reuse, not a claim that an answer alone completed a task.

Missing context, an empty cache or no safe match returns a miss. The caller must handle that result; this route alone does not prove an automatic fallback. Matching may incur usage charges. The practical opportunity is to reuse an eligible procedure instead of authoring it again, but we have not measured savings or speed here or verified availability for your account.

The product also describes an exact-response proxy cache in its open-source release section. That request/response cache and the verified-workflow path are distinct mechanisms; their eligibility and fallback behavior should not be mixed together.

One useful next test

Use a non-sensitive projection from this table. For Retool, connect a test data source and verify the intended user can read only the permitted data before adding a write operation. For Super, specify the destination and permitted action, then verify the resulting artifact. A local JSON export is neither a production permission test nor proof that either service ran successfully.
