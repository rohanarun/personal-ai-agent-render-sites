Make readiness actionable

A readiness signal should carry its timestamp, scope, and expiry conditions into the action that relies on it.

Trust recent proof

Reuse a fresh readiness result when the dependency is stable and the action consequence is bounded.

Probe the hinge

Run a focused readiness check when volatility or age could change whether the tool can fulfill the next step.

Defer with context

When probing is expensive and consequences are high, preserve the request rather than making a stale promise.

This simulation is a teaching model, not a production readiness policy. It demonstrates a contract-first pattern: timestamp readiness, model volatility, and gate consequential actions.
