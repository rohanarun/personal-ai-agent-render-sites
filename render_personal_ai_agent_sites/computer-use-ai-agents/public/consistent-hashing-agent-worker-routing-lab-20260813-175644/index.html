Place workers and keys together

Hash both into the same circular range. The first virtual node clockwise from a session key names its physical worker.

owner(k) = successor(hash(k))

Add one worker, move one slice

A new virtual node takes only keys between its predecessor and itself. Other ownership intervals remain untouched.

expected moved ≈ 1 / (n + 1)

Replicas smooth the ring

One physical worker receives several independent positions. More virtual nodes usually reduce load skew, at the cost of a larger routing table.

ring entries = workers × replicas

Agent-system actions

  • Keep session caches near their assigned worker.
  • Use weighted virtual nodes for unequal capacity.
  • Replicate critical state beyond the primary owner.
  • Drain workers before removing their final positions.
