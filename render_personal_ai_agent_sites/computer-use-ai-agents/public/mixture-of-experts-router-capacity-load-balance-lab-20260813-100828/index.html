Conditional computation

More parameters without using all of them.

A dense layer sends every token through the same weights. A sparse router scores several experts and dispatches each token to only the top one or two. The model can grow in capacity while per-token compute stays bounded—provided routing remains balanced.

The routing loop

Score. Select. Constrain.

Score each token.

A learned router turns the token representation into expert logits. Temperature and noise change how sharply those scores choose a specialist.

Keep only top-k.

The highest one or two gates survive. That sparse selection is the compute bargain: a large model stores many experts while each token activates very few.

Respect capacity.

Each expert receives a bounded number of token slots. Auxiliary balancing losses discourage collapse; capacity factors add headroom when traffic still clusters.

Failure modes

Expert collapse

One attractive expert receives most tokens while others sit idle. A balancing objective spreads importance and assignment counts.

Capacity overflow

A popular expert runs out of slots. Excess assignments are dropped or rerouted, trading quality, communication, and compute.

Router instability

Small score changes can flip the top expert. Noise and careful regularization can improve exploration without making dispatch chaotic.
