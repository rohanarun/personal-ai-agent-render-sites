Exactly once is an application contract.

The network can deliver requests more than once. Safety comes from naming the logical operation and remembering its first durable outcome.

1

Create one stable key.

The agent generates a unique key for the user’s intent and reuses it for every retry of that exact operation.

2

Store key and effect atomically.

The server reserves the key, commits the effect, and saves the response in one durable boundary. Concurrent duplicates wait or receive the stored receipt.

3

Bound the replay window.

The key expires after a documented retention period. A retry after expiry is a new risk, so clients must not retry forever.
