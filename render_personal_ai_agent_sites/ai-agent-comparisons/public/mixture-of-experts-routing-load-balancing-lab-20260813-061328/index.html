Sparsity is a routing contract not free capacity.

MoE replaces each dense feed-forward block with parallel experts and a learned gate. Parameter count can grow while active work per token stays bounded, but communication and balance become first-class system constraints.

The gate scores expert fit

A router projects each token representation into expert logits. Softmax turns those scores into gates; top-k keeps only the strongest destinations. Lower temperature sharpens small score differences.

g(x) = TopK(softmax(W_router x / temperature))

Capacity is finite

Each expert receives a fixed token budget per batch. A small capacity factor saves memory and communication but increases overflow. A large factor leaves expensive slack.

capacity = ceil(tokens x top_k / experts x factor)

Specialization

Useful experts learn different token regions. Weak specialization makes routing arbitrary; extreme specialization can funnel similar batches into one destination.

Load balancing

An auxiliary objective discourages unequal expert probability and assignment. Too little permits collapse. Too much can override semantic fit.

Sparse compute

Top-1 activates one expert per token; top-2 buys redundancy and smoother learning at roughly twice expert compute and communication.

Stress the simulator

Router collapse

A sharp gate repeatedly favors the same expert. Other experts receive weak gradients, specialization degrades, and the popular expert becomes a queue instead of a capability.

01

Capacity overflow

When routed tokens exceed an expert's capacity, the system must drop them, pass them through a residual path, or send them to a lower-ranked expert. Every policy changes quality or cost.

02

Balance without fit

Strong balancing can make assignment counts look perfect while tokens visit mediocre experts. Monitor routing confidence and task quality alongside expert load.

Choose the architecture by what can break.

Hover or focus each mechanism. The best routing scheme depends on accelerator topology, serving latency, expert placement, training stability, and the cost of overflow.

Top-1 routing

Switch

One destination per token minimizes expert compute and dispatch volume. Capacity and load balancing carry more pressure because there is no second expert.

active experts per token = 1
Top-2 routing

Redundant

Two weighted expert outputs improve routing continuity and gradient coverage, while doubling expert-side work compared with top-1.

y = gate_1 E_1(x) + gate_2 E_2(x)
Expert parallelism

Distributed

Experts live on different devices. All-to-all token dispatch can dominate runtime even when arithmetic is sparse.

latency = route + exchange + expert + combine
Shared experts

Common path

A dense shared expert can absorb general knowledge while routed experts specialize, trading extra compute for more stable coverage.

output = shared(x) + routed(x)
