Decode a decision, not a probability peak.

A language model defines a distribution over complete outputs. MAP decoding asks which single output has the highest probability. MBR asks which available decision performs best on average if the unknown reference were drawn from that distribution.

Expected utility turns samples into a decision.

For each candidate, compare it with every sampled pseudo-reference. Average those utilities and select the candidate with the highest estimate.

h* = argmax_h (1/N) sum_y u(h, y)

MAP and MBR answer different questions.

MAP finds a probability mode. MBR finds a representative decision under a task-specific utility. They agree only in special cases.

h_MAP = argmax_h p(h | x)

Sampling approximates the expectation.

More references reduce Monte Carlo variance, but every extra sample costs inference and metric evaluation.

The metric defines the task.

Token overlap rewards wording. Semantic metrics reward meaning. A poor utility can confidently optimize the wrong property.

risk(h) = E_y[1 - u(h,y)]

Candidate and reference sets may differ.

Practical systems can sample a reference set, rerank a smaller candidate set, or reuse the same samples for both.

Y ~ p(y|x), H subset of Y

Consensus is only as good as its evidence.

Small samples make winners jump.

With four pseudo-references, one unusual draw can move the decision. The convergence view replays the estimate as samples arrive, making Monte Carlo uncertainty visible rather than hiding it behind a final score.

Utility metrics carry values.

A semantic metric can overlook exact names or numbers. Token overlap can punish valid paraphrases. MBR does not remove metric bias; it operationalizes the metric more directly.

The model distribution can still be wrong.

Expected utility under a miscalibrated, biased, or narrow model remains bounded by that model's samples. Better decision theory cannot manufacture missing modes or factual evidence.

Audit the full decoding system.

Candidates
Is the answer in the set?

Reranking cannot select a sequence that was never proposed. Track oracle utility alongside realized MBR utility.

References
Are samples representative?

Inspect temperature, truncation, dependence, and duplicate rates. Sample count alone does not guarantee useful coverage.

Utility
Does the metric match deployment?

Validate metric rankings against human judgments and task outcomes, including names, numbers, safety, and minority modes.

Cost
Is the gain worth reranking?

Measure generation, pairwise scoring, batching, latency, and memory together. Expected utility has a systems price.
