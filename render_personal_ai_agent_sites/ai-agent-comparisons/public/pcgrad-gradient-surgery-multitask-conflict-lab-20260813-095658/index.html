When tasks fight, change the gradient.

A shared model can learn several objectives at once—until one task’s update harms another. PCGrad detects negative gradient alignment and removes the conflicting component before the optimizer steps.

Destructive interference

A useful update for one task can damage another.

Each task proposes a vector through shared parameter space. A positive dot product means the proposals broadly agree. A negative dot product means conflict: stepping along one can increase the other task’s loss. Gradient surgery edits that geometry instead of pretending the objectives are one.

Rotate two tasks, expose conflict, project the harmful component.

The two-dimensional vectors make the operation visible. Real models apply the same dot products and projections across millions of shared parameters.

The operation

Detect. Project. Recombine.

Measure alignment.

Compute the cosine similarity between task gradients. Negative similarity identifies a local update conflict, not a permanent incompatibility between tasks.

Remove the opposition.

PCGrad subtracts from one gradient its projection onto the other when their dot product is negative. Non-conflicting pairs remain untouched.

Pass the edited update onward.

Sum the projected task gradients and hand that vector to SGD, Adam, or another optimizer. Gradient surgery changes the proposed update, not the model architecture.

Important limits

Exactly opposite

When gradients point in opposite directions, projection can leave no useful shared update. The objectives may require a tradeoff or separate capacity.

Noisy minibatches

Instantaneous stochastic gradients can misrepresent persistent task relationships. Conflict statistics should be tracked over time.

More than two tasks

Projection order can matter. PCGrad randomizes pair order; alternatives optimize explicit worst-task, Pareto, or bargaining objectives.
