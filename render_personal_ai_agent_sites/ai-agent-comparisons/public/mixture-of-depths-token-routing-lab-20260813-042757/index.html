Capacity turns routing into competition.

A block processes only its top-k token scores. Easy tokens can bypass safely, but a weak router or tight capacity may crowd out the positions that need depth most.

Dense width is not the only place to make computation conditional.

Route tokens, not experts.

At each layer, rank token positions with a learned scalar router. Process the top-k positions through the transformer block and send the rest through the residual path.

Predictable tensors.

A fixed capacity keeps per-layer workload bounded, making conditional depth easier to batch than unconstrained halting.

Routing quality

The router must recognize which tokens benefit from extra transformation, not merely which positions look unusual.

Budget allocation

Higher capacity reduces misses but gives back compute savings. The useful frontier depends on workload difficulty.

Causal tracing

Inspect how often each token is routed and whether skipped layers alter the final answer, calibration, or long-context recall.

Three ways a cheap route becomes an expensive mistake.

Capacity collapse

Too many hard tokens compete for too few slots, so some demanding positions repeatedly bypass the computation they need.

Router blur

Flat scores make top-k selection unstable. Tiny perturbations can swap critical and easy tokens at the capacity boundary.

Depth starvation

A token can survive one bypass yet fail when skipped repeatedly. Measure path length distributions, not only average FLOPs.
