Why the tail survives.

The digest does not reserve equal space for equal latency intervals. It reserves detail according to rank, so the extremes receive finer centroids.

1. Sort by observed latency

Every tool call becomes a scalar observation. The digest maintains centroids ordered by their means, so a rank walk can reconstruct an approximate cumulative distribution without retaining every event.

centroid = (weighted mean, count)

2. Limit mass by quantile

Near the median, many observations may share a centroid. Near p99, the admissible mass shrinks. That uneven budget is the key: extreme quantiles get more local resolution than the crowded center.

k(q) ∝ compression × arcsin(2q − 1)

3. Merge without raw events

Each agent shard can summarize locally. A coordinator merges centroid summaries into another digest. The result is compact, composable telemetry for distributed agents, though it remains an approximation rather than a raw audit log.

digest(A ∪ B) ≈ merge(digest(A), digest(B))

Read the tradeoff before choosing the compression.

More compression

Raises the centroid budget and usually improves tail accuracy, but uses more memory. In this lab, compression controls the maximum target centroid count.

Mergeable summaries

Shards send weighted centroids rather than raw traces. Recompression after merging can add error, so compare the merge tab against the single-digest path.

Quantiles, not identities

A t-digest answers distribution questions. It cannot tell you which request caused the p99 spike. Pair it with sampled traces when root-cause identity matters.
