Distributed routing for agent systems

Move one shard. Not every agent memory.

Consistent hashing maps sessions around a ring. Add or remove a memory node and only the neighboring interval moves, keeping caches warm and agents attached to their context.

Why the ring holds.

A distributed agent system needs stable ownership more than perfect symmetry. Virtual nodes spread each physical shard around the address space while successor lookup limits disruption.

1

Hash shards into positions.

Each memory shard receives several virtual tokens. More tokens generally smooth the distribution, because every physical shard owns multiple small intervals instead of one large arc.

2

Route each session clockwise.

A session key becomes a point on the same ring. Its owner is the first token encountered clockwise, so every key has one deterministic destination without a central routing table.

3

Change one neighborhood.

When a shard joins, it captures only the intervals immediately before its tokens. When it leaves, those intervals pass to the next tokens. The rest of the ring keeps its assignments.
