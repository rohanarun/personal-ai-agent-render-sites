Compensation is a new transaction.

Commit locally, remember globally

Each participant owns its local transaction. The saga records enough durable state to know what completed and what can be compensated.

T₁ → T₂ → T₃ → T₄

Unwind in reverse order

If the third action fails, compensate the second and then the first. Never compensate work that did not commit.

fail(T₃) ⇒ C₂ → C₁

Undo is semantic

A refund does not erase a charge. A correction does not unsend a message. Compensations create auditable business facts that restore invariants.

compensate ≠ rollback

Agent-system actions

  • Persist a saga ID and idempotency key.
  • Make every compensation retry-safe.
  • Surface failed compensations for repair.
  • Choose orchestration or choreography deliberately.
