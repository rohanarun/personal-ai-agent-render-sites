Data stays distributed

One model, many private datasets.

A server broadcasts shared parameters. Selected clients train copies on local examples, return only model updates, and the server aggregates them. The loop is simple; the geometry is not. Unequal, non-IID datasets make local optima disagree.

One communication round

Broadcast. Train. Aggregate.

Select clients.

The server samples a fraction of available devices or institutions. Partial participation reduces communication, but the observed population changes each round.

Optimize locally.

Each participant takes several gradient steps on its own data. More local work saves communication while increasing drift when client distributions disagree.

Combine updates.

FedAvg weights client models by local example count. Proximal objectives restrain local departure; robust aggregators limit extreme coordinate updates.

Where federation strains

Statistical heterogeneity

Different users, hospitals, or devices observe different labels and features. Their best local updates need not align.

Systems heterogeneity

Clients vary in connectivity and compute. Stragglers, dropouts, and uneven participation reshape every server round.

Outlier updates

Faulty or adversarial clients can push extreme values. Robust rules help, but resilience and statistical efficiency trade off.
